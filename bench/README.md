## 怎么跑

对拍跑在自己的镜像里（[`../docker/Dockerfile.bench`](../docker/Dockerfile.bench)），
枢衡与三家竞品同处一室。

```bash
bash tests/bench/run.sh
```

这条命令建镜像、核对钉死的版本、然后在容器里把整条流水线跑一遍并断言判据两个方向
都判得动。**它不是对拍本身**，它是「对拍这套东西还活着」的门。

真正要出数的那天，在**合格宿主**上跑**启动器**（G145）：

```bash
BENCH_HOST_ATTEST="专机 · 无 TUN 代理" \
BENCH_SERVER_CPUS=0-1 BENCH_LOAD_CPUS=2-3 \
BENCH_DURATION=60s BENCH_CONNECTIONS=200 BENCH_WORKERS=2 \
BENCH_FULCRUM_BIN=/path/to/fulcrum \
  bash bench/docker-run.sh bench/out
```

★ ★ **⛔ 不要直接 `bash bench/run.sh`**（那是容器内那一步）。启动器做三件容器
自己做不到的事：在**宿主上**判 `net.core.netdev_max_backlog`（不符就拒绝启动）、
把另外四个键作为 `--sysctl` 旗标带进容器、把宿主实测值经环境变量传进去。
⇒ 绕过它起容器，快照拿不到那个凭证，**这一趟会被判成不合格** —— 那是有意的。

四步，顺序是承重的：**① 判据自测 → ② 环境快照与合格性 → ③ 逐类跑（只产原始数据）
→ ④ 判定**。①排最前的理由：判据坏掉最典型的形态是**它恒返回同一个答案**，
而那种坏法在后三步里长得和一切正常一模一样。

## 合格宿主

判据在 [`lib.sh`](lib.sh) 的 `bench_disqualifiers`，写成**纯函数** ——
读数由调用方传进来，⇒ 两个方向都能用合成输入当场证给人看
（`bash bench/lib.sh --self-check`）。**一条理由都打不出来 = 合格。**

**六条**，分成性质完全不同的三半（★ G145 把「内核参数」那一条从人写的声明里拆了出来）：

### 容器自己看得见的（机器判）

| 判据 | 不合格的形态 | 为什么 |
|---|---|---|
| `kernel` | 内核串里带 `microsoft` / `wsl` | Docker Desktop 的 Linux 侧跑在 WSL2 里。G132 记的实测理由是这台开发机上那个 TUN 代理**会干扰网络**（容器出不去 UDP/443）⇒ 这是唯一一条不需要人配合就判得死的证据 |
| `cpus` | 核数少于 `BENCH_MIN_CPUS`（缺省 4） | 负载生成器与被测**不许共享 CPU**，分不出两组就谈不上 |
| `load` | 1 分钟负载高于 `BENCH_MAX_IDLE_LOAD`（缺省 0.50） | 机器在干别的活，等于被测在与别人共享 CPU |
| `affinity` | 没有**同时**给 `BENCH_SERVER_CPUS` 与 `BENCH_LOAD_CPUS` | §9 的缓解项逐字写着基准环境要固化**内核参数与 CPU 亲和**。⚠ 只给一个等于没给 |

⚠ `affinity` 判的是「有没有钉到不相交的核上」，⛔ **不是**「钉得对不对」——
后者要看具体机器的拓扑，而那台机器今天不存在。

### 内核参数与资源上限（`kernel-params`，**G145 起是门，不再是声明**）

★ ★ ★ 这一格此前是下面那句人写的声明里的第三件。2026-09-06 的实测把那条路整个
否掉了 —— 两个方向都量过：

| 在宿主上设 | 新开的默认网络容器读到 |
|---|---|
| `net.ipv4.ip_local_port_range = 20000 60000` | 仍是 `32768 60999` |
| `net.core.somaxconn = 12345` | 仍是 `4096` |

那四个键是 **per-netns** 的，而对拍整个跑在自己 netns 的容器里
⇒ **一句完全诚实的「已固化」声明，对被测行为零影响**。
⚠ 这正是本仓最在意的那一族：一道恒绿的门与一道不存在的门，输出完全一样。

⇒ 六个键按「设得进哪里」重新分了三处，**每一处都有门**：

| | 键 | 在哪里设 | 谁判 |
|---|---|---|---|
| 容器侧 | `net.core.somaxconn` = 65535 · `net.ipv4.tcp_max_syn_backlog` = 65535 · `net.ipv4.ip_local_port_range` = `10240 65535` · `net.ipv4.tcp_tw_reuse` = **2** | `docker run --sysctl`（由 `bench/docker-run.sh` 从 `bench_container_sysctls` 推导）| `env-snapshot.sh` 在容器内逐条断言「实测==声明」|
| 宿主侧 | `net.core.netdev_max_backlog` = 16384 | `bench/sysctl.conf` → `/etc/sysctl.d/` | `bench/docker-run.sh` 在**宿主上**直读 `/proc/sys`，不符**拒绝启动** |
| 资源上限 | `nofile` = 1048576 | `docker run --ulimit` | `env-snapshot.sh` 核 `ulimit -n` |

- ⚠ `netdev_max_backlog` **设不进也读不到**容器（runc 当场拒绝；容器里 `/proc/sys/net/core/`
  下没有这个文件）⇒ 它只能宿主判，而启动器把宿主实测值经 `BENCH_HOST_SYSCTLS` 传进容器。
  ★ 绕过启动器手起容器 ⇒ 拿不到那个凭证 ⇒ **判成不合格**。
- ⚠ `tcp_tw_reuse` 声明成 **2 而不是 1**：`2` 的语义是「仅对环回启用」，而四家与 oha
  同处一个容器、只走环回 ⇒ 2 恰好覆盖本场景，1（全局）更宽却**不更贴切**。
- ⚠ ⚠ **`fs.file-max` 已从清单中移除**。★ 实测那台候选宿主上它是 `9223372036854775807`，
  而此前 `sysctl.conf` 里写的 `2097152` 是把它**往下压**。真正会咬的是每进程的
  `RLIMIT_NOFILE` —— ★ **实测容器缺省只有 1024**。⇒ 改设 `--ulimit nofile`。
- ★ `bench/sysctl.conf` 仍写明**有意不放进来的三类**（拥塞控制 · socket 缓冲 · `vm.*`）——
  它们会**改变结论本身**，而不只是消除噪声。

★ **这道门在每一次 `tests/bench/run.sh` 里两个方向都被走到**：门禁**有意不设**
`BENCH_HOST_SYSCTLS` ⇒ 容器侧四个键因旗标真的生效而**相符**（C13，正向），
宿主侧那一条因缺凭证而**判红**（C12，反向）。⛔ 别为了让输出好看去补那个变量。

### 容器原理上看不见的（要人声明：`BENCH_HOST_ATTEST`）

容器无从知道这台机器是不是在跑真业务、网络路径上有没有代理。⇒ 这两件只能由人写下来：

1. **这是专机** —— 没有在承载任何真业务（生产机不算合格宿主，它会与被测抢 CPU）
2. **网络路径上没有 TUN 代理 / VPN**

★ ★ **声明不是证明。** 这一格能做到的只有「谁都没声明过就一定不算合格」，
⛔ 它拦不住一句不实的声明 —— 那一格没有门，只有纪律。快照会把声明原文记下来。
⚠ **声明原文要如实**：这台机器上如果还有任何东西在跑（云厂商探针、隧道客户端），
⛔ 不是装作没有 —— 照实写进那句话里。

## 判定口径

判定在 [`verdict.sh`](verdict.sh)，它**先问宿主合不合格**：

- **不合格** ⇒ 逐条说出理由，写 `VERDICT: UNQUALIFIED`，然后停下 ——
  不取最强者、不算门槛、不打 PASS / FAIL。原始数据仍然完整落盘，
  ⚠ ⛔ 那份数据证明的是**流水线跑得通**，它不是、也不许被引用成性能读数。
- **合格** ⇒ 逐类判：

  ```
  该类最强者 = max(三家竞品在这一类的读数)      ⛔ 不是三家平均，⛔ 不是钉死某一家
  门槛       = 最强者 × 0.9                     （G19「不劣于 10%」，含等号）
  PASS       ⟺ 枢衡 ≥ 门槛
  ```

★ **「最强者」逐类现算。** §8 写着静态那一类比的是 nginx、L4 那一类比的是 HAProxy ——
枢衡要在**每一格**追上那一格的冠军。⛔ 跨类取最强者是错的。

⚠ 竞品集合是「除枢衡以外的全部」，**推导出来而不是写死的名单** ——
写死的名单在加第四家时没人会想起来去改，而它安静地少比一家。

⚠ ⚠ **方向今天只处理「越大越好」那一种。** 延迟类是反过来的；加第二类时要
显式给方向参数，⛔ 不许让判据去猜。

### 读数什么时候不算数

一份跑得飞快的 5xx 会给出非常好看的 `requestsPerSec`。⇒ [`read-raw.py`](read-raw.py)
在比较**之前**先校验每一份原始数据：`successRate` 必须**恰好** 1.0 ·
状态码分布里**只有** 200（⛔ 判「只有」不是判「有」）· 传输层错误为空。
任何一份不合格 ⇒ 这一类报 `NO-VERDICT`，⛔ 它不会被当成一个数悄悄排进去。

★ 用例脚本在**开跑前**还核过一次（状态码 + 字节数逐字节对）。两次核的不是同一段
时间：一次防「一开始就没在服务那个资源」，一次防「负载期间中途变坏」。

### ★★★ 压测端自己先饱和 ⇒ 这一类作废（判据 ④）

上面那几条守的都是**单份读数**坏掉。还有一种坏法，每一份读数都完美合格：
**负载生成器自己先到顶了。** 那时四家会一起收敛到 oha 的天花板，而
「不劣于最强者 10%」这条**照常打 PASS** —— 输出一组看起来完全正常、
其实量的是 oha 的数。⚠ 合格宿主那六条一条都答不了它：它们判的是这台机器合不合格，
而这里坏掉的是**量具本身到顶了**。

两条判据，性质完全不同：

| | 判什么 | 阈值 | 今天的地位 |
|---|---|---|---|
| **B 收敛** | 全场读数彼此挤在一起（`(最高−最低)/最高` 低于阈值）| `BENCH_MIN_SPREAD`（缺省 **0.05**）| ★ **承重**。不需要任何新测量，用已采到的那组数 |
| **A 绝对天花板** | 最强者越过「生成器上限 × headroom」| `BENCH_GEN_HEADROOM`（缺省 **0.90**）| ⏳ **可选**。要 `raw/<类>/ceiling.txt` 里有个数，没有就整条不参与 |

B 的依据：nginx（C）· HAProxy（C）· Caddy（Go）· 枢衡（Rust/pingora）是四套结构
完全不同的实现，它们落进同一个百分点里，**「共享了某个外部上限」远比「它们真的
一样快」更可能**。⚠ 它说不出是哪一个上限（生成器 / 环回 / 亲和）——
⛔ 别把它读成「一定是 oha 饱和了」，它只说**这组数不可比**。

⚠ ⚠ **A 今天有意不是承重件**：它的正确性整个压在「参照服务真的比四家都快」这一条上，
而那条在合格宿主到位之前**验不了** —— 参照选慢了就恒作废，选的是另一个真实服务器
则量到的是 `min(oha, 那个服务器)`，天花板被低估。⇒ 参照服务选定那天再打开它。
⛔ ⚠ 那个文件**不许叫 `ceiling.json`**：`read-raw.py` 对该目录做 `glob("*.json")`，
一个 `.json` 会被当成第五家被测混进竞品集合，而那不会有任何东西说。

### ★★★ 2026-09-06：第一趟真实数据之后，这两个阈值的回核

原文写的是「`0.05` 与 `0.90` 没有实测支撑，它们是判断不是读数，**第一次在合格宿主上
跑完之后要回头核**」。跑完了，回核结论如下。

**`BENCH_MIN_SPREAD = 0.05`：这一趟没误报，但暴露了 B 的一个真实缺陷。**

| | |
|---|---|
| 全场 spread `(最高−最低)/最高` | **0.8599** ⇒ 远高于 0.05，不作废 ✔ |
| ⚠ ★ 最快两家 haproxy vs nginx | **0.0071** —— **低于 0.05** |

⚠ ⚠ ★ **两套结构完全不同的实现（C 写的 nginx 与 C 写的 HAProxy，架构差异极大）
落进 0.71% 以内，正是 B 声称要怀疑的形状 —— 而 B 一声没吭。**
原因在判据的形状里：B 取的是**全场极差**，而枢衡的慢（0.86）把它整个撑开了。
⇒ **一个慢的被测会掩盖掉快的那几家之间的收敛。**

★ 这条是第一组真实数据给出的、可以推翻原设计的证据 —— 正是「回头核」要的东西。
⏳ **怎么修还没拍**（候选：改判「最快的 k 家之间的收敛」，或对每一对都判）。
⛔ 在拍之前不要把 `0.05` 当成「已被实测确认的阈值」。

**`BENCH_GEN_HEADROOM = 0.90`：仍然验不了。**

A 这一趟没打开（没有 `ceiling.txt`）⇒ 这个数**一次都没被执行过**。
⚠ 而这一趟恰恰给出了「为什么需要 A」的第一个真实理由：haproxy/nginx 收敛在
~54.5k，**与「oha 在 2 个核上到顶」的形状一致**，而本套东西证不了它们不是撞到了
量具的天花板。⇒ 选定参照服务那天再回来。

★ 误判方向是**有意不对称**的：一次误作废只是**扣下一个结论**，一次漏判是**给出一个
错结论** ⇒ 两条都往「作废」那侧倒，且**「判不了」（有效读数不足两条 / 上限不是正数）
一律作废，⛔ 不算通过**。判定报 `VOID`。

## 四家怎么摆平

配置模板在 [`conf/`](conf/)，是交付物的一部分 —— 第三方要看的就是那四份配置本身。

| 对齐项 | 口径 |
|---|---|
| **一次只起一家** | 四家同时跑会互相抢 CPU，量到的是「四家一起跑」这件事 |
| **同一个 payload** | `/dev/urandom` 出的固定字节数（缺省 4096），同一个 URL 路径。★ 用随机字节而不是可压缩的重复字节：本类**不比压缩** |
| **访问日志全关** | 日志是另一件事，开着会把它的代价算进吞吐 |
| **明文 HTTP/1.1 + keep-alive** | TLS 归「TLS 握手」那一类，⛔ 不混进来 |
| **权限身份一致** | 四家在容器里都是 root。⚠ nginx 因此要显式 `user root`（只搬二进制搬不到官方镜像里那个系统用户），⛔ 不许改成只给它降权 —— 降权本身对吞吐有代价 |
| **worker 数一致** | `BENCH_WORKERS`，**缺省 1**，见下 |

### ★ worker 数：四家各自的旋钮，以及第一刀是怎么撞出一个缺陷的

| 被测 | 旋钮 |
|---|---|
| 枢衡 | `threads_l7`（全局块）|
| nginx | `worker_processes` |
| HAProxy | `nbthread` |
| Caddy | `GOMAXPROCS`（Go，没有 worker 进程的概念）|

⚠ ⚠ ★ **枢衡那一格是这一刀跑通之后才有的。** 2026-09-05 之前它走 pingora
`ServerConf::default()`（`threads: 1`），DSL 与 CLI 都没有调它的口子 ⇒ 四家当时
**唯一可对齐的值只有 1**。那条缺陷（D33）由 **G140** 结案：线程数按 service 角色定缺省
（L7 = CPU 核数 · L4 = 2 · 管理面与后台 = 1），三格都可被配置覆盖。

★ 这是「第一刀的价值在于把整条流水线真的跑一遍」的活样本 ——
**那个缺的旋钮不是想出来的，是撞出来的。**

`BENCH_WORKERS` 缺省仍取 **1**：它与机器无关 ⇒ 门禁里那一趟在任何机器上读数一致。
⛔ **真要出数那天必须显式设它**（按那台合格宿主的 CPU 分配）——
「四家都跑各自的缺省」与「四家跑同一个 worker 数」是两个不同的实验，
⚠ 而它们的差别在报告里看不出来，除非环境快照里那个数被读到。

### ⚠ HAProxy 在「静态吞吐」这一类里做的事更少

HAProxy **不是文件服务器**。它靠 `http-request return ... file <路径>` 回一个固定
body —— 那是它能做到的最接近「服务一个静态资源」的事，但它**不做目录、不做条件
请求、不做 range**。

⇒ 这一类量的是「把同一个固定 body 推出去有多快」，而 §8 的「静态吞吐」正是这个意思。
⚠ ⚠ **但这条口径不许在引用数字时被丢掉**：它少做了几件事，
⇒ 若它在这一类领先，那个领先里有一部分来自它没做的那几件。

## 钉死的版本

★ 全部按 **digest / sha256** 钉死，⛔ 不按浮动 tag：tag 浮动意味着今天绿的那一趟
和明天绿的那一趟用的不是同一个被测对象，而对拍的全部价值建立在
「换的只有被测的那一家」上。

| 用途 | 版本 | 来源 digest |
|---|---|---|
| nginx | 1.29.1 | `nginx@sha256:8adbdcb969e2676478ee2c7ad333956f0c8e0e4c5a7463f4611d7a2e7a7ff5dc` |
| HAProxy | 3.2.3 | `haproxy@sha256:baecd003ae5c2376e58d04a5b2ffc7d82d30e9bebe2869f76222b819f719dee3` |
| Caddy | 2.10.2 | `caddy@sha256:4c6e91c6ed0e2fa03efd5b44747b625fec79bc9cd06ac5235a779726618e530d` |
| 运行基座 | Debian trixie slim | `debian@sha256:d7e12182ce18b85b93007c1dedf31f2d29e01ccf3182cc4017c709b6259bc132` |
| 负载生成器 | oha v1.15.0 | 与 `Dockerfile.build` 里那一份**必须同版本同 sha256** |

⚠ **改 `Dockerfile.bench` 就要改这张表**：`tests/bench/run.sh` 的门 ① 把表里的
digest 与 Dockerfile 里的逐条对上，门 ② 把两张镜像里的 oha 对上。⛔ 单独改一边会红。

★ 基座必须与 `Dockerfile.build` **同一个 Debian 代号**：枢衡的二进制在那张镜像里
编出来，动态链接 glibc。⚠ nginx 与 haproxy 是从 bookworm 搬到 trixie 上的，
SONAME 同名而 **Debian 包名不同**（bookworm 的 `libssl3` 在 trixie 叫 `libssl3t64`）。

## 产物布局

```
<输出目录>/
  env.json                       环境快照 + 合格性判定（schema: fulcrum-bench-env/1）
  raw/<用例类>/<被测>.json        oha 的原始输出，原样落盘
  verdict.txt                    判定结论，或「为什么不出结论」
```

★ `raw/` 下的东西是 G19 要求「全部公开」的那份**原始数据**。⛔ 不要在提交时
筛掉「不好看」的那几趟 —— 那样公开的就不是原始数据了。

## ⛔ 这套东西证不了什么

- ⚠ **它给出的结论只有一类、只有一趟、只有一台机器**（2026-09-06 静态吞吐，见本页开头）。
  ⛔ 别把那一格读成 M3 的整体结论 —— §8 划了七类，这是第一类。
- ⛔ **它说不了枢衡为什么慢。** 那一趟只是读数，本目录不含任何根因结论。
- **它只跑「静态吞吐」一类。** §8 划了七类（静态吞吐 · 反代吞吐 · TLS 握手 ·
  L4 转发 · 缓存命中 · 长连接 · 高并发短连接），第一刀按 G132 只做一类 ×
  三家 —— 因为「该类最强者」这个概念还没被检验过，先铺覆盖面是在检验之前铺。
- **`tests/bench/run.sh` 全绿 ≠ 对拍达标。** 它判的是流水线活着、判据判得动。
- **合格性里那两件靠声明的事没有门**（专机 · 无 TUN 代理）。★ G145 把第三件
  （内核参数）从声明里拆出来变成了门，⛔ 但那**没有**让这两件也变得可验证。
- **判据 ④ 说不出压测端到底有没有饱和。** 承重的那一半（B 收敛）只回答「这组数
  不可比」，⛔ **它分不出是生成器到顶、环回到顶、还是 CPU 亲和没分开**。真正能直答
  这一问的是 A（绝对天花板），而 **A 今天没打开** —— 它要一个「确实比四家都快」的
  参照服务，那个选择在合格宿主到位之前验不了。⇒ 在 A 打开之前，「oha 没有先饱和」
  这句话**本套东西证不了**，它只能证「四家的数彼此分得开」。
- **`BENCH_MIN_SPREAD` / `BENCH_GEN_HEADROOM` 这两个阈值没有实测支撑**（见上一节）。
- **容器里读到的 sysctl 仍然不是宿主的** —— G145 没有改变这一点，它改变的是
  **我们不再假装那两者是一回事**：四个 per-netns 键改成在容器里设、在容器里判，
  宿主那一个在宿主上设、在宿主上判。快照把容器实测记成 `sysctl_as_seen_in_container`，
  把两侧声明与宿主实测记成 `kernel_params`，⇒ 第三方可以自己重算那次比较。
  ⚠ ⛔ 但它**证不了宿主上那个值在整趟对拍期间没被改过** —— 启动器只在开跑前读一次。
- **`netdev_max_backlog` 那道门证不了 16384 就够用。** ★ 够不够是可以量的：
  `/proc/net/softnet_stat` 第 2 列就是这一项的丢包数（实测它是全局的，容器里读到的
  就是宿主的）⇒ **对拍前后各读一次**才是那个判据，⛔ 而本套东西今天还没有自动读它。
