## ★ 这份数据说得了什么

- **枢衡在这一类上落后一个数量级**，且落后于 Caddy（Go）。
- ⚠ **它不是偶发卡顿，是每请求均匀地慢**：p99（46 ms）比 Caddy（49 ms）还低，
  最慢值（72 ms）远好于 nginx（207 ms）。★ 200 并发 ÷ 7638 rps = **26.2 ms**，
  与实测 p50（26.23 ms）逐位吻合 ⇒ **并发全部堵在吞吐上限后面**，不是尾延迟问题。
- **`net.core.netdev_max_backlog` 没有溢出**：`/proc/net/softnet_stat` 第 2 列
  跑前跑后四个核**全部为 0**（该值这一趟设的是 16384）。
  ⚠ ⛔ 这**不**说明出厂值 1000 也够 —— 那一趟没跑过。

## ⛔ 这份数据说不了什么

- ⚠ ⚠ ★ **说不了 haproxy/nginx 的 54.5k 是它们自己的上限还是 oha 的天花板。**
  两套结构完全不同的实现落在 **0.71%** 以内，这正是判据 ④ 声称要怀疑的形状；
  而能直答此问的判据 A（绝对天花板）今天没打开（要一个「确实比四家都快」的参照服务）。
  ★ **但这不动摇 FAIL**：若 54.5k 真是量具的顶，真实最强者只会更高 ⇒ 门槛只会更高。
  ⇒ **FAIL 在两个方向上都成立。**
- **说不了枢衡为什么慢。** 本目录只是读数，⛔ 不含任何根因结论。
- **只跑了七类里的一类**（§8：静态吞吐 · 反代吞吐 · TLS 握手 · L4 转发 ·
  缓存命中 · 长连接 · 高并发短连接）。⛔ 别把这一格读成整体结论。
- ⚠ **HAProxy 在这一类里做的事更少** —— 它不是文件服务器，靠
  `http-request return … file` 回一个固定 body，不做目录 / 条件请求 / range。
  ⇒ 它的领先里有一部分来自它没做的那几件（`bench/README.md` 逐字写着这条，
  ⛔ 引用数字时不许丢掉）。

## 口径

同机 · 同用例 · 同负载生成器（oha 1.15.0）· 明文 HTTP/1.1 + keep-alive ·
访问日志四家全关 · 同一个 4096 字节随机 payload · **四家 worker 数一律 2**
（枢衡 `threads_l7` · nginx `worker_processes` · HAProxy `nbthread` · Caddy `GOMAXPROCS`）。

宿主 4 核 ⇒ 被测钉 `0-1`、负载生成器钉 `2-3`（⚠ 恰好压线，只能 2+2 分）。
60 秒 × 200 连接 × 4 家，一次只起一家。

完整环境（内核 · CPU · 内核参数声明与实测 · 被测版本 · 产物 sha256）见 [`env.json`](env.json)。
