### ⛔ ⛔ 這一類的「最強者」與「門檻」兩個數不可引用

對齊口徑第 ⑥ 條要求四家都重複使用上游連接，判法是每千請求新建的上游連接數不超過 50
（`bench/lib.sh` 的 `BENCH_UPSTREAM_REUSE_MAX`）。本趟 **caddy 69.62 超限**；
**nginx 21.26** 雖在限內，也比開發機上對齊時的實測區間（0.68–3.20）高出近 7 倍。
逐家數字在 [`raw/reverse-proxy-throughput/upstream-conns.txt`](raw/reverse-proxy-throughput/upstream-conns.txt)。

**證據指向設定**：[`Caddyfile-proxy`](../../conf/Caddyfile-proxy) 的
`keepalive_idle_conns_per_host` 與 [`nginx-proxy.conf`](../../conf/nginx-proxy.conf)
的 `keepalive` 都是 **64**，而本趟是 **200 並行**；這個口徑只在門禁（10 連接）與
開發機 spike（50 連接）下驗過，**從沒在視窗參數下驗過**。重複使用對齊的兩家恰好是沒有
這個上限的那兩家（haproxy 0.71、樞衡 1.89）。
⚠ 這是強證據，⛔ 還不是單變數驗證 —— 把上限調到不低於並行數、在 200 並行下復量一次
那個比值，才算坐實。那一步**不需要合格宿主**：重複使用比值與宿主合不合格無關。

⚠ **本趟為什麼沒被門攔住**：C20（`tests/bench/gate.sh`）判的是門禁那一趟；
視窗裡跑的是 `bench/docker-run.sh`，**不經過 gate** ⇒ 這一格只能靠人看。

★ **但 `FAIL` 這個結論方向穩健**：

- 不復用上游只會讓那一家**更慢**（多出來的建連落在與源站共享的 server 組核上）。
  本儲存庫在開發機上實測過這個方向：caddy 補上覆用之後 rps **11690.2 → 13266.1**
  （`Caddyfile-proxy` 註解原文）。
- 樞衡自己是對齊的（1.89）⇒ 它的讀數不受影響。
- ⇒ 按正確口徑重跑，最強者只會更高、門檻只會更高，而樞衡不變 ⇒ **`FAIL` 只會更遠**。
- ⛔ 但**具體的最強者與門檻**（12971.5 / 11674.4）被壓低了，**不許當成這一類的真值引用**；
  「0.631 倍」同理只是上界。

### 這一類另外三條已知不對等（引用數字時一直帶著）

[`bench/README.md`](../../README.md) 逐字寫著，這裡重述：

1. **樞衡那一趟是 fulcrum→fulcrum**，四家裡只有它的源站與被測同二進位
   ⇒ 方向對樞衡不利：`PASS` 更可信，⛔ **`FAIL` 不許拿這一條去辯解**。
2. **源站與被測共享 server 組的核** ⇒ 本類絕對讀數**不可與靜態吞吐並排比較**。
3. **payload 與靜態吞吐不是同一份位元組**（本類是可列印的 base64，靜態吞吐是 `/dev/urandom`）。

## 診斷讀數（⛔ 不是 §8 的類別，不參與判定）

| 讀數 | req/s | p50 | p99 | 最慢 |
|---|---:|---:|---:|---:|
| 樞衡 `respond`（同一份 4096 位元組，**不走檔案**） | 34360.8 | 5.75 ms | 11.77 ms | 34.4 ms |
| 樞衡 `file_server` | 19729.5 | 10.05 ms | 14.02 ms | 58.4 ms |
| 樞衡快取 · 記憶體命中 | 28461.0 | 7.03 ms | 11.06 ms | 41.6 ms |
| 樞衡快取 · 磁碟命中 | 13544.9 | 14.80 ms | 20.27 ms | 86.8 ms |

- **`respond` 上界**回答的是「把檔案那條路修到零成本，最多能到哪」。實測 **34360.8**，
  是靜態吞吐門檻 52466.3 的 **0.655 倍**。
  ★ 旁證：[`diag/respond-ceiling/`](diag/respond-ceiling/) 裡 `file_server` 那個變體
  （19729.5）與靜態吞吐那一類裡的樞衡（19811.2）只差 0.4% ⇒ 兩處量的是同一條路徑。
- **`G150` ② 那一格**：磁碟命中 p99 − 記憶體命中 p99 = **9.22 ms**（20.27 − 11.06），
  見 [`diag/cache-hit-p99/delta.json`](diag/cache-hit-p99/delta.json)。兩個後端跑完後
  `Age` 分別是 62 / 61 秒，都不短於 60 秒的負載時長 ⇒ **整趟沒有發生重驗證**，差值算數。
  ⚠ `G150` ② **有意不定閾值** —— 本目錄只交這個數，⛔ 不據它判任何事。

## 有效性

八份 §8 讀數與四份診斷讀數全部 `successRate = 1.0`，狀態碼只有 200，傳輸層錯誤只有
良性的 `aborted due to deadline`（每份不超過 200 條，即連接數 —— 負載時長到點時
仍在路上的那些請求）。

`/proc/net/softnet_stat` 第 2 列（`netdev_max_backlog` 溢出丟包）跑前跑後四個核**全部為 0**
（該值本趟設的是 16384）。

## ⛔ 這份資料說不了什麼

- **說不了樞衡為什麼慢。** 本目錄只是讀數，⛔ 不含任何根因結論。
- **說不了 nginx / haproxy 的靜態吞吐是它們自己的上限還是 oha 的天花板** —— 判據 A
  （絕對天花板）仍沒打開。★ **但這不動搖 `FAIL`**：若那是量具的頂，真實最強者只會更高。
- **靜態吞吐的新舊兩組不可並排比較。** 與 2026-09-06 那組相比，至少三格口徑不同：
  站台根的檔案系統（那組跑在把站台根挪到 ext4 的提交 `c387732` 之前，站台根落在容器
  可寫層；那組 `env.json` 還沒有 `site_root` 這一格，本組記著 `ext4`）、`payload_bytes`
  的記錄（那組是 `null`）、被測二進位。⇒ ⛔ 兩組樞衡讀數之間的倍數**沒有意義**，別算。
- **只跑了 §8 七類裡的兩類。** 其餘五類（TLS 握手 · L4 轉發 · 快取命中 · 長連接 ·
  高並行短連接）沒跑；⚠ 上面那格快取 p99 是診斷讀數，**不是**「快取命中」那一類。
- ⚠ **HAProxy 在靜態吞吐裡做的事更少**（靠 `http-request return … file` 回固定 body，
  不做目錄 / 條件請求 / range），`bench/README.md` 逐字寫著這條，⛔ 引用數字時不許丟。

## 口徑

同機 · 同用例 · 同負載生成器（oha 1.15.0）· 明文 HTTP/1.1 + keep-alive · 訪問紀錄四家全關 ·
**四家 worker 數一律 2** · 宿主 4 核 ⇒ 被測釘 `0-1`、負載生成器釘 `2-3`（與 2026-09-06 逐字相同）·
60 秒 × 200 連接，一次只起一家 · **payload 4096 位元組，本趟顯式設定**。

開跑前執行指令碼自己再核了一遍：該機六類業務處理程序**逐類 0 個**（判在處理程序上，⛔ 不判 systemd
狀態），1 分鐘負載 0.02。

被測二進位 `0.1.0+g6bf1f3fe0618`，sha256
`8ca94d3d1db11194b6a5ce811b8677857f46c7864e9f1e1c2318fee114b8c256`（18 397 216 位元組），
在開發機上按 G107 於容器內建置，投遞到宿主。
⚠ `env.json` 裡 `fulcrum_build_id` 的末尾粘了一段無關字元（`…0618HeadersResetPriority…`）——
`bench/env-snapshot.sh` 取版本串的正則沒有收尾邊界，把二進位裡緊挨著的字母一併吞了。
**以本節的版本串與 sha256 為準**；`env.json` 按原始資料的規矩不回填。

對拍鏡像 `fulcrum-bench:local` 沒有重建（`docker/Dockerfile.bench` 自 2026-09-05 起沒改過，`G36`）。

完整環境見 [`env.json`](env.json)。宣告原文按 owner 2026-09-06 定下的規則做過去標識化，
改了什麼見 [`REDACTION.md`](REDACTION.md)。

## 重現

```bash
BENCH_HOST_ATTEST="<你自己那台机器的声明>" \
BENCH_SERVER_CPUS=0-1 BENCH_LOAD_CPUS=2-3 \
BENCH_WORKERS=2 BENCH_DURATION=60s BENCH_CONNECTIONS=200 BENCH_PAYLOAD_BYTES=4096 \

  bash bench/docker-run.sh bench/out
```

⚠ 先把 `bench/sysctl.conf` 應用到宿主，否則啟動器會拒絕啟動（G145）。
