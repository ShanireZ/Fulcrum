### ⛔ ⛔ 这一类的「最强者」与「门槛」两个数不可引用

对齐口径第 ⑥ 条要求四家都复用上游连接，判法是每千请求新建的上游连接数不超过 50
（`bench/lib.sh` 的 `BENCH_UPSTREAM_REUSE_MAX`）。本趟 **caddy 69.62 超限**；
**nginx 21.26** 虽在限内，也比开发机上对齐时的实测区间（0.68–3.20）高出近 7 倍。
逐家数字在 [`raw/reverse-proxy-throughput/upstream-conns.txt`](raw/reverse-proxy-throughput/upstream-conns.txt)。

**证据指向配置**：[`Caddyfile-proxy`](../../conf/Caddyfile-proxy) 的
`keepalive_idle_conns_per_host` 与 [`nginx-proxy.conf`](../../conf/nginx-proxy.conf)
的 `keepalive` 都是 **64**，而本趟是 **200 并发**；这个口径只在门禁（10 连接）与
开发机 spike（50 连接）下验过，**从没在窗口参数下验过**。复用对齐的两家恰好是没有
这个上限的那两家（haproxy 0.71、枢衡 1.89）。
⚠ 这是强证据，⛔ 还不是单变量验证 —— 把上限调到不低于并发数、在 200 并发下复量一次
那个比值，才算坐实。那一步**不需要合格宿主**：复用比值与宿主合不合格无关。

⚠ **本趟为什么没被门拦住**：C20（`tests/bench/gate.sh`）判的是门禁那一趟；
窗口里跑的是 `bench/docker-run.sh`，**不经过 gate** ⇒ 这一格只能靠人看。

★ **但 `FAIL` 这个结论方向稳健**：

- 不复用上游只会让那一家**更慢**（多出来的建连落在与源站共享的 server 组核上）。
  本仓在开发机上实测过这个方向：caddy 补上复用之后 rps **11690.2 → 13266.1**
  （`Caddyfile-proxy` 注释原文）。
- 枢衡自己是对齐的（1.89）⇒ 它的读数不受影响。
- ⇒ 按正确口径重跑，最强者只会更高、门槛只会更高，而枢衡不变 ⇒ **`FAIL` 只会更远**。
- ⛔ 但**具体的最强者与门槛**（12971.5 / 11674.4）被压低了，**不许当成这一类的真值引用**；
  「0.631 倍」同理只是上界。

### 这一类另外三条已知不对等（引用数字时一直带着）

[`bench/README.md`](../../README.md) 逐字写着，这里重述：

1. **枢衡那一趟是 fulcrum→fulcrum**，四家里只有它的源站与被测同二进制
   ⇒ 方向对枢衡不利：`PASS` 更可信，⛔ **`FAIL` 不许拿这一条去辩解**。
2. **源站与被测共享 server 组的核** ⇒ 本类绝对读数**不可与静态吞吐并排比较**。
3. **payload 与静态吞吐不是同一份字节**（本类是可打印的 base64，静态吞吐是 `/dev/urandom`）。

## 诊断读数（⛔ 不是 §8 的类别，不参与判定）

| 读数 | req/s | p50 | p99 | 最慢 |
|---|---:|---:|---:|---:|
| 枢衡 `respond`（同一份 4096 字节，**不走文件**） | 34360.8 | 5.75 ms | 11.77 ms | 34.4 ms |
| 枢衡 `file_server` | 19729.5 | 10.05 ms | 14.02 ms | 58.4 ms |
| 枢衡缓存 · 内存命中 | 28461.0 | 7.03 ms | 11.06 ms | 41.6 ms |
| 枢衡缓存 · 磁盘命中 | 13544.9 | 14.80 ms | 20.27 ms | 86.8 ms |

- **`respond` 上界**回答的是「把文件那条路修到零成本，最多能到哪」。实测 **34360.8**，
  是静态吞吐门槛 52466.3 的 **0.655 倍**。
  ★ 旁证：[`diag/respond-ceiling/`](diag/respond-ceiling/) 里 `file_server` 那个变体
  （19729.5）与静态吞吐那一类里的枢衡（19811.2）只差 0.4% ⇒ 两处量的是同一条路径。
- **`G150` ② 那一格**：磁盘命中 p99 − 内存命中 p99 = **9.22 ms**（20.27 − 11.06），
  见 [`diag/cache-hit-p99/delta.json`](diag/cache-hit-p99/delta.json)。两个后端跑完后
  `Age` 分别是 62 / 61 秒，都不短于 60 秒的负载时长 ⇒ **整趟没有发生重验证**，差值算数。
  ⚠ `G150` ② **有意不定阈值** —— 本目录只交这个数，⛔ 不据它判任何事。

## 有效性

八份 §8 读数与四份诊断读数全部 `successRate = 1.0`，状态码只有 200，传输层错误只有
良性的 `aborted due to deadline`（每份不超过 200 条，即连接数 —— 负载时长到点时
仍在路上的那些请求）。

`/proc/net/softnet_stat` 第 2 列（`netdev_max_backlog` 溢出丢包）跑前跑后四个核**全部为 0**
（该值本趟设的是 16384）。

## ⛔ 这份数据说不了什么

- **说不了枢衡为什么慢。** 本目录只是读数，⛔ 不含任何根因结论。
- **说不了 nginx / haproxy 的静态吞吐是它们自己的上限还是 oha 的天花板** —— 判据 A
  （绝对天花板）仍没打开。★ **但这不动摇 `FAIL`**：若那是量具的顶，真实最强者只会更高。
- **静态吞吐的新旧两组不可并排比较。** 与 2026-09-06 那组相比，至少三格口径不同：
  站点根的文件系统（那组跑在把站点根挪到 ext4 的提交 `c387732` 之前，站点根落在容器
  可写层；那组 `env.json` 还没有 `site_root` 这一格，本组记着 `ext4`）、`payload_bytes`
  的记录（那组是 `null`）、被测二进制。⇒ ⛔ 两组枢衡读数之间的倍数**没有意义**，别算。
- **只跑了 §8 七类里的两类。** 其余五类（TLS 握手 · L4 转发 · 缓存命中 · 长连接 ·
  高并发短连接）没跑；⚠ 上面那格缓存 p99 是诊断读数，**不是**「缓存命中」那一类。
- ⚠ **HAProxy 在静态吞吐里做的事更少**（靠 `http-request return … file` 回固定 body，
  不做目录 / 条件请求 / range），`bench/README.md` 逐字写着这条，⛔ 引用数字时不许丢。

## 口径

同机 · 同用例 · 同负载生成器（oha 1.15.0）· 明文 HTTP/1.1 + keep-alive · 访问日志四家全关 ·
**四家 worker 数一律 2** · 宿主 4 核 ⇒ 被测钉 `0-1`、负载生成器钉 `2-3`（与 2026-09-06 逐字相同）·
60 秒 × 200 连接，一次只起一家 · **payload 4096 字节，本趟显式设置**。

开跑前运行脚本自己再核了一遍：该机六类业务进程**逐类 0 个**（判在进程上，⛔ 不判 systemd
状态），1 分钟负载 0.02。

被测二进制 `0.1.0+g6bf1f3fe0618`，sha256
`8ca94d3d1db11194b6a5ce811b8677857f46c7864e9f1e1c2318fee114b8c256`（18 397 216 字节），
在开发机上按 G107 于容器内构建，投递到宿主。
⚠ `env.json` 里 `fulcrum_build_id` 的末尾粘了一段无关字符（`…0618HeadersResetPriority…`）——
`bench/env-snapshot.sh` 取版本串的正则没有收尾边界，把二进制里紧挨着的字母一并吞了。
**以本节的版本串与 sha256 为准**；`env.json` 按原始数据的规矩不回填。

对拍镜像 `fulcrum-bench:local` 没有重建（`docker/Dockerfile.bench` 自 2026-09-05 起没改过，`G36`）。

完整环境见 [`env.json`](env.json)。声明原文按 owner 2026-09-06 定下的规则做过去标识化，
改了什么见 [`REDACTION.md`](REDACTION.md)。

## 复现

```bash
BENCH_HOST_ATTEST="<你自己那台机器的声明>" \
BENCH_SERVER_CPUS=0-1 BENCH_LOAD_CPUS=2-3 \
BENCH_WORKERS=2 BENCH_DURATION=60s BENCH_CONNECTIONS=200 BENCH_PAYLOAD_BYTES=4096 \
BENCH_FULCRUM_BIN=/path/to/fulcrum \
  bash bench/docker-run.sh bench/out
```

⚠ 先把 `bench/sysctl.conf` 应用到宿主，否则启动器会拒绝启动（G145）。
⚠ 反代吞吐那一类要在这组参数下对齐，得先解决上面那条上游复用的口径。
判定口径与「它证不了什么」在 [`bench/README.md`](../../README.md)。
