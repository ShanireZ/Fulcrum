## 与窗口二并排时能说到哪一步

静态吞吐那一类与两个诊断步骤，自窗口二（`0ea0f56`）以来**用例脚本、四家配置、启动器与判定脚本一个字节都没改**
（`fulcrum-respond.Fulcrumfile` 只改了注释），宿主、对拍镜像、内核参数与四个负载参数也逐字相同。
变的是**枢衡二进制**（`6bf1f3f` → `0d79113`：其间落地了 `G155` 写缓冲 16 KiB、字面量正文不再每请求拷贝、
请求头不再整份克隆、`G156` 指标注册表分片）—— **以及窗口之间的漂移**：

| 读数 | 窗口二 | 本组 | 变化 |
|---|---:|---:|---:|
| nginx 静态吞吐 | 58295.94 | 53967.40 | −7.43% |
| haproxy 静态吞吐 | 53868.79 | 50944.93 | −5.43% |
| caddy 静态吞吐 | 11679.76 | 11274.28 | −3.47% |
| **枢衡静态吞吐** | 19811.18 | 19540.17 | −1.37% |
| 枢衡 `respond` | 34360.76 | 35443.61 | +3.15% |
| 枢衡 `file_server` | 19729.49 | 19302.55 | −2.16% |

⇒ 三家竞品的二进制两次相同，却漂了 −3.5% 到 −7.4% ⇒ **窗口间漂移与枢衡这几笔改动的量级相当**，
⛔ 两组枢衡读数之差**不许归因**到那几笔改动上（无论哪个方向）。能说的只有：那几笔改动在这台宿主上
带来的变化（若有）**没有大过窗口间漂移**，⇒ 跨窗口量不出来；要量它得在同一窗口里交替跑改前改后两个二进制
（[`ws-off/`](ws-off/README.md) 就是这么量 `work_stealing` 的）。
⛔ 开发机上的诊断读数不是性能声明（`G139`），⛔ 也别按比例折算到这台宿主上。

## 有效性

12 份 §8 读数与 4 份诊断读数全部 `successRate = 1.0`，状态码只有 200，传输层错误只有
良性的 `aborted due to deadline`（每份不超过 200 条，即连接数 —— 负载时长到点时仍在路上的那些请求）。

`/proc/net/softnet_stat` 第 2 列（`netdev_max_backlog` 溢出丢包）跑前跑后四个核**全部为 0**
（该值本趟设的是 16384）。

## ⛔ 这份数据说不了什么

- **说不了枢衡为什么慢。** 本目录只是读数，⛔ 不含任何根因结论。
- **说不了 nginx / haproxy 的静态吞吐是它们自己的上限还是 oha 的天花板** —— 判据 A
  （绝对天花板）仍没打开。★ **但这不动摇 `FAIL`**：若那是量具的顶，真实最强者只会更高。
- **说不了 `ws-off/` 那一趟该不该进产品。** 那是同一窗口里的诊断，被测的不是产品二进制；
  `G35` 怎么定以 [`PLAN.md`](../../../PLAN.md) 为准。
- **只跑了 §8 七类里的三类。** 其余四类（TLS 握手 · L4 转发 · 缓存命中 · 长连接）没跑；
  ⚠ 上面那格缓存 p99 是诊断读数，**不是**「缓存命中」那一类。
- ⚠ **HAProxy 在静态吞吐里做的事更少**（靠 `http-request return … file` 回固定 body，
  不做目录 / 条件请求 / range），`bench/README.md` 逐字写着这条，⛔ 引用数字时不许丢。
- ⚠ 每一格只跑了一趟（60 秒），没有重复 ⇒ 给不出趟间区间。

## 口径

同机 · 同用例 · 同负载生成器（oha 1.15.0）· 明文 HTTP/1.1（keep-alive 除高并发短连接那一类外都开）·
访问日志四家全关 · **四家 worker 数一律 2** · 宿主 4 核 ⇒ 被测钉 `0-1`、负载生成器钉 `2-3`
（与 2026-09-06、2026-09-10 逐字相同）· 60 秒 × 200 连接，一次只起一家 · payload 4096 字节，显式设置。

开跑前运行脚本自己再核了一遍：该机六类业务进程**逐类 0 个**（判在进程上，⛔ 不判 systemd 状态），
1 分钟负载 0.13（环境快照取的是 0.28）。

被测二进制 `0.1.0+g0d7911335ccd`，sha256
`63cbaf5624fc2593e4e53dec15fbeb8c28dea9a6591972e83d6e56dbc518e193`，在开发机上按 G107 于容器内构建、
投递到宿主；源码还原后重编一次 sha256 逐字相同（窗口清单 5d′ ④）。`env.json` 的 `fulcrum_build_id`
这一次是干净的版本串（`b043126` 修了窗口二里那段粘连）。

对拍镜像 `fulcrum-bench:local` 没有重建（`docker/Dockerfile.bench` 自 2026-09-05 起没改过，`G36` / `G152`）。

完整环境见 [`env.json`](env.json)。原始数据与从宿主取回的原件逐字节相同，只有两处例外：
声明原文按 owner 2026-09-06 定下的规则做过去标识化；两份 `oha-request.txt` 的行尾 CRLF 转成了 LF。
改了什么、怎么核的，见 [`REDACTION.md`](REDACTION.md)。

## 复现

