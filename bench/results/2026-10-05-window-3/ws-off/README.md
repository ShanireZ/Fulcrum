## 被測是什麼

產品提交 `0d79113` 上**只多一行**：`crates/fulcrum-server/src/process.rs` 的 `build_server_conf` 裡，
`graceful_shutdown_timeout_seconds` 那一行下面插

```rust
        work_stealing: false,
```

在開發機上按 G107 於容器內建置（`git diff --numstat` 恰好 `1	0`），取出後**原始碼還原並重編一次**，
重編結果與上一級目錄那個產品二進位 sha256 逐字相同 ⇒ 兩個二進位只差這一行。⛔ 這一行**沒有提交**。

| | sha256 |
|---|---|
| 本趟（`fulcrum-ws-off`） | `8198a3a32224fb71041653615aec5ca7895628a68b5c12c2e3631f55dd21f254` |
| 上一級目錄（產品） | `63cbaf5624fc2593e4e53dec15fbeb8c28dea9a6591972e83d6e56dbc518e193` |

⚠ 兩者的版本串**相同**（`0.1.0+g0d7911335ccd`，版本串只認提交）⇒ **只憑 sha256 區分**；
本目錄 [`env.json`](env.json) 的 `fulcrum_sha256` 是前者。

⚠ 這個二進位只適合拿來跑這幾類：關工作竊取是全域項，而 L4 的 accept 循環與 QUIC 的 `Action::Accept`
每條連接用裸 `tokio::spawn` ⇒ 那兩種連接會全擠在 accept 那一個執行緒上。本趟三類與兩個診斷都只走明文 h1，不受影響。

## 怎麼跑的

與上一級目錄**同一次停服、同一條命令**裡，排在 M3 那一趟之後；兩趟的 `BENCH_*` 參數由執行指令碼裡
同一個函式給出 ⇒ **逐字相同**，只換產物與輸出目錄。第一趟結束後等 1 分鐘負載降到 ≤ 0.50
（等了 1 分 45 秒，降到 0.49）才起第二趟；`env.json` 判**合格**，`qualified: true`、`disqualifiers: []`。

## ⛔ 這份資料說不了什麼

- **說不了為什麼。** 靜態 / `file_server` / 快取命中這幾格往上、短連接那一類往下、反代那一類 p99 變差，
  機制本目錄**一條都沒查**，⛔ 不含任何根因結論。
- **說不了「關掉就是純收益」。** 關掉工作竊取的已知代價是連接線上程間分佈不均時忙的執行緒沒法把活分出去；
  本趟三類都是 200 條均勻的連接，這個代價能不能顯出來本趟**判斷不了**，而短連接那一類已經是一個反例。

- **說不了合在一起夠不夠過門檻**：本趟靜態吞吐是門檻的 0.434 倍。
