## 被测是什么

产品提交 `0d79113` 上**只多一行**：`crates/fulcrum-server/src/process.rs` 的 `build_server_conf` 里，
`graceful_shutdown_timeout_seconds` 那一行下面插

```rust
        work_stealing: false,
```

在开发机上按 G107 于容器内构建（`git diff --numstat` 恰好 `1	0`），取出后**源码还原并重编一次**，
重编结果与上一级目录那个产品二进制 sha256 逐字相同 ⇒ 两个二进制只差这一行。⛔ 这一行**没有提交**。

| | sha256 |
|---|---|
| 本趟（`fulcrum-ws-off`） | `8198a3a32224fb71041653615aec5ca7895628a68b5c12c2e3631f55dd21f254` |
| 上一级目录（产品） | `63cbaf5624fc2593e4e53dec15fbeb8c28dea9a6591972e83d6e56dbc518e193` |

⚠ 两者的版本串**相同**（`0.1.0+g0d7911335ccd`，版本串只认提交）⇒ **只凭 sha256 区分**；
本目录 [`env.json`](env.json) 的 `fulcrum_sha256` 是前者。

⚠ 这个二进制只适合拿来跑这几类：关工作窃取是全局项，而 L4 的 accept 循环与 QUIC 的 `Action::Accept`
每条连接用裸 `tokio::spawn` ⇒ 那两种连接会全挤在 accept 那一个线程上。本趟三类与两个诊断都只走明文 h1，不受影响。

## 怎么跑的

与上一级目录**同一次停服、同一条命令**里，排在 M3 那一趟之后；两趟的 `BENCH_*` 参数由运行脚本里
同一个函数给出 ⇒ **逐字相同**，只换产物与输出目录。第一趟结束后等 1 分钟负载降到 ≤ 0.50
（等了 1 分 45 秒，降到 0.49）才起第二趟；`env.json` 判**合格**，`qualified: true`、`disqualifiers: []`。

## ⛔ 这份数据说不了什么

- **说不了为什么。** 静态 / `file_server` / 缓存命中这几格往上、短连接那一类往下、反代那一类 p99 变差，
  机制本目录**一条都没查**，⛔ 不含任何根因结论。
- **说不了「关掉就是纯收益」。** 关掉工作窃取的已知代价是连接在线程间分布不均时忙的线程没法把活分出去；
  本趟三类都是 200 条均匀的连接，这个代价能不能显出来本趟**判断不了**，而短连接那一类已经是一个反例。
- **每格只有一趟**（60 秒），没有重复 ⇒ 给不出趟间区间；上表的「竞品漂移」是唯一的对照。
- **说不了合在一起够不够过门槛**：本趟静态吞吐是门槛的 0.434 倍。
