## 与窗口三并排时能说到哪一步

两趟之间**用例脚本、四家配置、启动器与判定脚本一个字节都没改**（`bench/` 只改了 `env-snapshot.sh` / `snapshot-json.py`
多记 CPU 拓扑，与 `README.md`），宿主、对拍镜像、内核参数、亲和与四个负载参数也逐字相同。
变的是**枢衡二进制**（`0d79113` → `39cfb7d`：文件那条路正文不另拷 `c8a89d0`、构响应头不分配 `5824b3f`、

## 有效性

12 份 §8 读数与 4 份诊断读数全部 `successRate = 1.0`，状态码只有 200，传输层错误只有
良性的 `aborted due to deadline`（每份不超过 200 条，即连接数）。

`/proc/net/softnet_stat` 第 2 列（`netdev_max_backlog` 溢出丢包）跑前跑后四个核**全部为 0**（该值本趟设的是 16384）。

## ⛔ 这份数据说不了什么

- **说不了枢衡为什么慢。** 本目录只是读数，⛔ 不含任何根因结论。
- **说不了 nginx / haproxy 的静态吞吐是它们自己的上限还是 oha 的天花板** —— 判据 A
  （绝对天花板）仍没打开。★ **但这不动摇 `FAIL`**：若那是量具的顶，真实最强者只会更高。
- **只跑了 §8 七类里的三类。** 其余四类（TLS 握手 · L4 转发 · 缓存命中 · 长连接）没跑；
  ⚠ 上面那格缓存 p99 是诊断读数，**不是**「缓存命中」那一类。
- ⚠ **HAProxy 在静态吞吐里做的事更少**（靠 `http-request return … file` 回固定 body，
  不做目录 / 条件请求 / range），`bench/README.md` 逐字写着这条，⛔ 引用数字时不许丢。
- ⚠ 每一格只跑了一趟（60 秒），没有重复 ⇒ 给不出趟间区间。

## 口径

同机 · 同用例 · 同负载生成器（oha 1.15.0）· 明文 HTTP/1.1（keep-alive 除高并发短连接那一类外都开）·
访问日志四家全关 · **四家 worker 数一律 2** · 宿主 4 核 ⇒ 被测钉 `0-1`、负载生成器钉 `2-3`
（与 2026-09-06、09-10、10-05 上午逐字相同；`host.cpu_topology` 记下这两组各是一个物理核）·
60 秒 × 200 连接，一次只起一家 · payload 4096 字节，显式设置。

开跑前运行脚本自己再核了一遍：该机六类业务进程**逐类 0 个**（判在进程上，⛔ 不判 systemd 状态）。
⚠ 那一刻 1 分钟负载 **0.47**（环境快照取的也是 0.47），贴着合格线 0.50 —— 是停服动作本身留下的，合格判定照常成立。

被测二进制 `0.1.0+g39cfb7dbeba6`，sha256
`a90b6036be5b7dc2e7c17c3d3070cbfbc3b39272450a58bb32517cfd66528562`，在开发机上按 G107 于容器内构建、
投递到宿主；全部源码刷新 mtime 后强制重编一次，sha256 逐字相同（窗口清单 5d）。

对拍镜像 `fulcrum-bench:local` 没有重建（`docker/Dockerfile.bench` 自 2026-09-05 起没改过，`G36` / `G152`）。

完整环境见 [`env.json`](env.json)。原始数据与从宿主取回的原件逐字节相同，只有两处例外：
声明原文按 owner 2026-09-06 定下的规则做过去标识化；`oha-request.txt` 的行尾 CRLF 转成了 LF。
改了什么、怎么核的，见 [`REDACTION.md`](REDACTION.md)。
