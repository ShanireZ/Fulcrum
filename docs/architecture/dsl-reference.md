# 一、总览：一份配置长什么样

```text
# 全局选项块（可选，必须在最前）
{
    acme_email  ops@example.com
    admin       unix//run/fulcrum/admin.sock
}

example.com {
    encode gzip
    header /static/* Cache-Control "public, max-age=3600"
    reverse_proxy 127.0.0.1:3000
}

api.example.com {
    @internal remote_ip 10.0.0.0/8
    handle @internal {
        reverse_proxy 10.0.0.1:8080 10.0.0.2:8080 {
            lb_policy       least_conn
            health_uri      /health
            health_interval 5s
            dns_refresh     30s
        }
    }
    respond 403
}
```

★ 上面这个例子只有在 `handle` 跑在 `respond` **之前**时才成立——见 §三。

## 全局选项块能写什么

| 选项 | 形式 | 说明 |
|---|---|---|
| `acme_email` | `acme_email <邮箱>` | ACME 账户邮箱（G53）|
| `acme_ca` | `acme_ca <目录 URL>` | 换 CA（默认 Let's Encrypt）|
| `admin` | `admin unix/<路径>` | 管理面监听地址（G8/G14）|
| `default_sni` | `default_sni <域名>` | 客户端**不带** SNI 时当作它报了这个名字。⚠ 它**不**给「报了、而我们没有那张证书」的 SNI 兜底 —— 那种连接照旧被拒绝握手（Caddy 把后者另立为 `fallback_sni`，枢衡没有）|
| `auto_http_redirect` | `auto_http_redirect <true\|false>` | 自动把 HTTP 跳到 HTTPS（G12）。★ **不写就是 `true`**，见 §二 |
| `grace_period` | `grace_period <时长>` | 优雅停机的排空窗口。★ 不写＝ **30s**，见[部署](/platform/deploy.md) |
| `proxy_protocol_from` | `proxy_protocol_from <网段…>` | ★ ★ **信任这些来源发来的 PROXY 头**，管 **HTTP 面全部监听端口**（M2 批 D）。不写＝**谁都不信**。见下 |

★ **凭据不在这里，也不在 DSL 的任何地方**（G59）：DNS 供应商的 token 只从
文件或环境变量读——DSL 是要被 diff、被贴进 issue、被版本控制的东西。

## ★ ★ ★ `proxy_protocol_from`：不在清单里，就一个字节都不读

前面挂了 L4 负载均衡器（云 LB、HAProxy、另一台枢衡）时，真实客户端 IP 只能靠
**PROXY protocol** 带进来 —— 它是连接开头的一小段字节，不是 HTTP 头。

| 来源 | 枢衡怎么做 |
|---|---|
| **在清单里** | 读那个头，`remote_ip` 匹配器与访问日志用**头里的**地址 |
| **不在清单里** | ★ ★ **一个字节都不读**，那几个字节原样当作应用数据 |

⚠ ⚠ **它与[安全基线](/platform/security-baseline.md)里 XFF 那条是同一口径
（「不在清单里就当没有这个头」），但落法不同，而这个不同必须说清楚**：
XFF 是 HTTP 头，忽略它无害；PROXY 头是**连接开头的字节**，
「读掉丢弃」与「一个字节都不读」是**给上游两条完全不同的流**。

★ 取「一个字节都不读」的两条理由：

1. 它与 L4 分流那条「**不终止 TLS、只看一眼、字节原样重放**」是同一条纪律 ——
   **枢衡不替上游做决定**。
2. ★ ★ 更硬的那条：v2 的头**自带一个 u16 长度字段**，
   「读掉丢弃」必须先解析**攻击者控制**的那两个字节才知道该丢多少 ——
   而「不读」完全不碰。

⚠ **代价写在明处**：清单配错了（该信的没写进去），上游会收到那 12/16 字节，
若它自己不认 PROXY 头就会协议错乱。★ 那是**「你配错了」的正确症状**，
不是枢衡替你猜错了 —— 而猜错的症状是「客户端 IP 有时对有时不对」，那种要难查得多。

★ **`LOCAL` 命令与 `PROXY UNKNOWN` 不是错误**：它们表示「这条连接没有真实客户端」
（**上游 LB 的健康检查就长这样**）—— 头照样吃掉，客户端地址仍用 socket 对端。
⚠ 把它们判成坏头，现场表现是**每一次健康检查都断连**。

## ~~回落后端~~ —— ⚠ ⚠ **整层（M2 批 G）删除**

§6.3 那个过渡层的用户是**逐块归零**的：`l4`（批 B）→ `file_server`（批 F）→
`cache`（批 G）⇒ **一个都不剩**，于是 `fallback_nginx` / `fallback_caddy`
两条全局选项**一并删除**，比 §6.3 原本写的「1.0 时归零」提前。

⚠ **写了它们的配置现在编译不过**，而报的**不是**「未知的全局选项」——
有一条专门的诊断（`FUL-DSL-0034`）告诉人这一层去哪了、现在该怎么写。
★ 一个公开配置面消失时，最起码的交代是说清它没了、为什么、现在怎么办；
只回「你是不是想写 XXX」等于让写过它的人以为自己打错了字，而它当初是对的。

★ ★ 那一层留下两句话，在别处照样成立：

1. **501 与 502 是两个不同的事实，不许合并** —— 501 = 配置里没写，502 = 写了但连不上。
   合并之后，一次配置遗漏与一次后端故障在现场长得一模一样。
2. **一个静静躺着的死配置，与一个正在生效的配置，在配置文件里长得一模一样** ——
   所以那一层当初会在装载日志里说「配了但没有任何路由会用到它」。

★ 枢衡**不拉起、不监管、不重启、不读**任何外部引擎的配置（G34）——
这一条没有随回落层消失，它是产品边界。那两个后端进程现在可以停掉了。

# 二、站点块的地址

| 写法 | 含义 |
|---|---|
| `example.com` | HTTPS（自动 HTTPS，G12），并自动把 HTTP 重定向过来（**合成一个 `:80` 站点**，见下）|
| `*.example.com` | 通配符，**只吃一层**（见下）。★ **需要 DNS-01**（G54/G57），M1 即可用（G58）|
| `http://example.com` | 明确 HTTP，**不自动升级、不签证书** |
| `example.com:8443` | 指定端口 |
| `:8080` | 任意 Host 的该端口 |
| `a.com, b.com { … }` | 多地址共用一个块 |

★ ★ **通配符只吃一层，这是公开契约的一部分**（G66）：

| 站点写法 | `a.example.com` | `example.com` | `a.b.example.com` |
|---|---|---|---|
| `*.example.com` | ✅ 中 | ❌ 不中（裸域） | ❌ 不中（多一层） |

⚠ **不是「后缀匹配」**。这与 **RFC 6125、浏览器的实际行为、以及 Caddy** 一致，
更要紧的是它与**证书那一侧完全一致**——一张 `*.example.com` 的证书本来就服务不了
`a.b.example.com`。★ 两侧共用同一份实现（`fulcrum_config::host::wildcard_covers`），
所以这张表不会与代码分家。
★ 想覆盖多层，就把 `*.b.example.com` 也写成一个站点块。

⚠ **上表就是全部**。M1 **不支持 IPv6 字面量地址**（`[::1]:8443` 这种）——
这是已知限制，不是疏漏；写了会得到一条点名说明这件事的诊断，
而不是一句关于端口或字符集的、指错方向的抱怨。

## ★ ★ 自动 HTTP 重定向：它是**一个真的站点块**，不是数据面里的特判

写 `example.com` 时，编译器会**合成**这样一个站点：

```text
http://example.com {
    redir https://{host}{uri} 308
}
```

★ ★ **合成物出现在 `fulcrum compile` 的 JSON 与 `fulcrum plan` 的输出里** ——
它是可以被读到、被 diff、被质疑的事实，而不是「产品自己知道的一件事」。
⚠ 一条看不见的特判，在它某天行为不对时，用户手上没有任何东西可查。

| 规则 | 说明 |
|---|---|
| 状态码 | **308**，不是 301/302 —— 308 保留方法与 body，否则一个 `POST` 会变成 `GET`（现场表现是「表单提交丢了」）|
| 自己写了 `http://<同一主机名>` | **不合成那一个**，你的写法优先 |
| 已经有 `:80` 端口兜底站点 | 仍然合成，**但会给一条 warning**（`FUL-DSL-0030`）：站点索引是「精确 → 通配 → 端口兜底」，合成的是精确匹配，会把那几个主机名从兜底站点手里接走 |
| 关掉 | 全局块里 `auto_http_redirect false`（⚠ 是 `false`，DSL 的布尔不认 `off`，见 §七）|

★ ★ **它顺带把 HTTP-01 修好了**：G54 把 HTTP-01 定为「备」，而**没有 80 端口就没有落脚点** ——
一台 443 被挡住的机器会永远签不出证书，且换不了挑战方式。
⚠ 挑战应答跑在**路由之前**，所以这条 308 吃不到它。

> ⚠ ⚠ **这一节从前是一句空话。** 表里那句「并自动把 HTTP 重定向过来」
> 印了三个月，而代码里一行都没有：`plan` 只列 `https :443`，80 端口上没有任何监听。
> 它是上线当天 `curl http://example.com` 连不上时才被发现的。
> ★ 文档与实现对不上时，**先问哪一边是对的** —— 这一次是文档对、实现欠着。

★ **无站点匹配时返回 421**（G63），不静默交给任何站点——见 §八。

# 三、执行顺序表（G49）——★ 这是公开契约

站点块内的指令**按下表顺序执行，不按书写顺序**。这是 G49 拍板的形状（照 Caddy），
换来的是「用户随便写也能跑对」与 Caddyfile 迁移零意外。

| 序 | 指令 | 类别 | 归属 |
|---|---|---|---|
| 10 | `tracing` | 中间件 | 预留 |
| 20 | `header` | 中间件 | M1 自研 |
| 30 | `rewrite` | 中间件 | M1 自研 |
| 40 | `encode` | 中间件 | M2 自研 |
| 50 | `cache` | 中间件 | M2 自研 |
| 55 | `handle` | 容器 | M1 自研 |
| 56 | `route` | 容器 | M1 自研 |
| 60 | `redir` | 终结 | M1 自研 |
| 70 | `respond` | 终结 | M1 自研 |
| 75 | `metrics` | 终结 | M2 自研 |
| 80 | `reverse_proxy` | 终结 | M1 自研 |
| 90 | `file_server` | 终结 | M2 自研 |

> ★ **这张表就是代码里那张表。** `crates/fulcrum-config/src/directive.rs` 的 `chain_directives!`
> 是它的代码侧，`crates/fulcrum-config/tests/doc_contract.rs` **逐行比对两边**——
> 改了一侧没改另一侧，测试会红。契约不靠自觉维护。

- **中间件**按序依次执行，可叠加。
- **容器**（`handle` / `route`）决定块内那些指令怎么跑，本身不产生行为。
- **终结类第一个匹配即停**，其后的终结指令不再考虑。

## ★ 容器为什么也占表位（落地时补）

拍板当天这张表里只有九条，配套说明写的是「容器不参与排序」。落地时发现那句话**留了一个洞**：
容器与普通指令之间的先后就没有定义了，而按「不在表里的排最后」接住，
**本页 §一那个示例当场就是错的**——

```text
handle @internal { reverse_proxy … }
respond 403                            # 兜底
```

`respond` 在第 70 步；`handle` 若排在它后面，那条 403 会恒胜，
**handle 块永远进不去，而配置能装载、请求能通、日志一行不报**。
这正是 G49 配套第 2 条点名要防的那个形状。

所以容器进表，位置在**中间件之后、终结类之前**：先按匹配分派（`handle`），
再给保序块一次机会（`route`），最后才是站点级的兜底终结指令。
★ 这是**对 G49「照 Caddy」的落实，不是新决策**——Caddy 的 order 列表里
`handle` / `route` 同样各占一位。

## ★ ★ ★ 三条配套约束，缺一不可

1. **`route { … }` 是保序逃生口**：块内**按书写顺序**执行，顺序表不生效。
   没有它，「表决定一切」时用户无法表达例外。
   ⚠ 逃生口管的是**块内**：`route` 这个块自己仍然站在第 56 步上。
2. **新增指令必须在表里有位置，否则编译不过。** ⚠ 这是本页最容易烂掉的一处：
   若按「不在表里就排最后」处理，新指令会**悄悄跑在错误的位置上**——
   配置能装载、请求能通、日志一行不报。
   **做成编译期穷尽性检查，不是注释提醒。**
   ★ Caddy 自己就是这么做的（不在 order 列表里的指令直接报错）。
   ★ ★ **落地成两半，两半都要有**：① 序号写在 `chain_directives!` 每行的最前面，
   少了它编不过——**「忘了给位置」这个选项不存在**；② `compile.rs` 里对
   `ChainDirective` 的 `match` **没有 `_` 兜底臂**，「在表里有位置」≠「有人接」。
3. **错误提示要能解释位置**：执行顺序与书写顺序不同而出了意外时，
   诊断必须说出「它实际跑在第几步、为什么」，否则用户只能去背这张表。
   ★ 已落地：`FUL-DSL-0028` 在编译期就指出「你这条排在第 N 步，
   而第 M 步那条没有匹配器、会先终结请求」；`fulcrum plan` 把整条链连同步号打出来。

## 4.1 终结类

| 指令 | 形式 | 状态 |
|---|---|---|
| `reverse_proxy` | `reverse_proxy [matcher] <upstream…> { … }` | **M1 自研** |
| `respond` | `respond [matcher] <status> [body]` | **M1 自研** |
| `redir` | `redir [matcher] <to> [code]`，默认 302 | **M1 自研** |
| `file_server` | `file_server [matcher] [browse] { root … }` | **M2 自研**（批 F）|
| `metrics` | `metrics [matcher]` —— **不收任何参数、没有子块** | **M2 自研**（批 M）|

### `metrics`：Prometheus 抓取端点（G116）

```text
metrics.example:9443 {
    tls /etc/fulcrum/m.crt /etc/fulcrum/m.key
    @internal remote_ip 10.0.0.0/8
    handle @internal { metrics }
    respond 403
}
```

它是**普通站点块里的终结指令**，不是独立监听器、也不是站点级属性。
⇒ 访问控制（匹配器）、TLS、访问日志**全部复用现有机制**（G116 就是这三样），
而 [G14「管理面只绑 Unix socket」的口径一个字不动](/platform/security-baseline.md)
—— 指标面不属于管理面。响应是 `200`，`Content-Type: text/plain; version=0.0.4; charset=utf-8`。

⛔ **压缩不在其中**：`metrics` 与 `respond` / `redir` 同病 —— 三者写响应走的是同一条
没有 encoder 的路（`encode` 今天只接在 `file_server` 与转发那两处）。⇒ 在这个站点里
写一条 `encode gzip`，**对抓取端点一个字节都不影响**：响应仍是 `200`、正文仍然正确，
只是 `Content-Encoding` 那一格不出现，而没有人会去看一个成功抓取的响应头。
代价见[可观测性](/architecture/observability.md)。

⚠ ⚠ **代价说在明处：指标与业务共用监听器，匹配器写错就会把指标暴露出去。**
这一条**架构兜不住，只能靠文档与诊断兜** —— 上面这段就是文档那一半，
`FUL-DSL-0037` 是诊断那一半：`metrics` 身上**没有任何限制得了来源的匹配器**时报一条
warning（`handle` / `route` 那层带着也算 —— 它罩住块内每一步）。

★ ★ ★ **算不算数，问的是「它能不能把两个发同样请求的客户端分开」**：

| 条件 | 算不算 | 为什么 |
|---|---|---|
| `remote_ip` | ✅ | socket 对端，在这一层伪造不了 |
| `header` | ✅ | 一个共享密钥可以放在这里 |
| `path` · `path_regexp` · `host` · `method` · `query` | ❌ | 全都是请求行与请求头里的东西，**任何客户端都能照着发一份** —— 它们只决定端点摆在哪，不减少能碰到它的人 |

⚠ ⚠ **所以 `handle /metrics { metrics }` 照样报警告**，而这正是这条诊断的重点：
从 nginx / Caddy 迁过来的人第一反应就是写一条路径，于是**最可能出现的那个裸奔配置**
恰恰是最先撞上来的那一个。⚠ `not { remote_ip … }` 仍然算保护。

★ 仍然判不动的那一半：**匹配器写得对不对**（网段圈没圈对、`header User-Agent Prometheus`
其实谁都挡不住）。编译期没有这些信息 ⇒ **宁可漏报也不误报** ——
一条报「已保护」的假话比没有诊断更坏。

⚠ 它排在 **75**，也就是 `respond` 之后。所以 `metrics @internal` 与一条兜底 `respond 403`
**并排写在站点块顶层是错的** —— 403 在第 70 步先终结。示例里那个 `handle`（第 55 步）
不是排版习惯，是唯一正确的写法；写错时 `FUL-DSL-0028` 会说出来。

★ 访问日志 `outcome` 那个闭集因此**从 7 个值变成 8 个**，多的是 `metrics`
（`reverse_proxy` · `file_server` · `respond` · `redir` · `error` · `no_site_match` ·
`acme_http01` · **`metrics`**）。闭集靠数据面一个穷尽 `match` 守着：加一种就编不过。

⚠ 结构化配置是**公开入口**（G11），所以它的 JSON 形状也是契约：这一步序列化成
`{"order":75,"matcher":…,"directive":"metrics"}`，**没有第二个键**。

指标清单、每一格的基数上界与取数点见[可观测性](/architecture/observability.md)。

### `reverse_proxy` 的子块

| 子指令 | 说明 | 状态 |
|---|---|---|
| `lb_policy` | `round_robin`（默认）／`least_conn`／`ip_hash`／`random` | M1 |
| `health_uri` | 主动健康检查路径（G17）。✅ **已接线**（批 11，G77）。★ **不写它就完全不探测** —— 其余 `health_*` 有默认值也不会让探测发生 | M1 |
| `health_interval` / `health_timeout` | 默认 `10s` / `3s`，**打点下界 500ms**。★ 每条 `reverse_proxy` 各自的 `health_interval` 真的算数（**不像 `dns_refresh` 那样全库取最小值** —— 探测是打在别人服务上的流量）。⚠ `health_timeout` 罩的是**整趟**（连接 + 写 + 读）| M1 |
| `health_status` | 认为健康的状态码，默认 `2xx`。★ 认不出的写法是**装载期错误**，不回落成默认 | M1 |
| `dns_refresh` | ★ 上游域名**定期重解析**（G17）。默认 `30s`，**下界 5s**。**这条直接消灭 nginx OSS 那个经典事故源**。✅ **已接线**（批 10，G76）。⚠ 打点节奏取**全库最小值**、每轮刷全部上游——配了 `60s` 的那条可能被更频繁地刷到（更频繁不是更稀疏，对正确性无影响） | M1 |
| `passive_fail` / `passive_window` | 被动熔断阈值与窗口（G17）。⚠ ⚠ **只到配置层为止**：DSL 认得它，而**运行时一步都不做** —— 它在 `fulcrum_runtime::UNWIRED` 里登记着，装载时会打出来。★ 主动健康检查（`health_uri`）是**另一件事**：那个打的是一个专门的探测路径，被动熔断看的是**真实流量**的失败率 | M1 |
| `header_up` / `header_down` | 改发往上游 / 回给客户端的头 | M1 |
| `transport` | `http`（默认）／`https` | M1 |
| `tls_insecure_skip_verify` | 上游用 https 时跳过证书校验。⚠ 只给自签的内网上游用 | M1 |
| `id` | ★ **这一条 `reverse_proxy` 的稳定名字**（M2 批 N，G125），**选填**，一个参数。管理面的临时覆盖层用 `(站点名, id, 上游地址)` 三格寻址「**这个站点块**里的那台机器」；没写 `id` 的那条，那一格**就是空串** —— 这不是第二套寻址，只是同一个键空间里 id 可以为空。<br>★ ★ **同一个站点里两条 `reverse_proxy` 的 `(id, 上游地址)` 相同 ⇒ 它们共享同一个覆盖格子**，一次 `disable` 把这几条一起摘掉。⛔ **不是错误，也不给告警**：「一个后端挂在几组 `handle` 路由后面」是反代最常见的写法 ⇒ **现有配置一个字节都不用改**。★ 而「一起摘掉」多半正是要的语义：那台机器坏了，它不该从任何路由收流量。**想分开就给其中一条写一行 `id`**，写了就各占一格、各摘各的。<br>⚠ 「这一格覆盖管着几条 `reverse_proxy`」由 `GET /stats` 显示出来（G18「不持久化但永远可见」）—— 那是「以为 `disable` 只影响一条」这件事唯一的提醒。<br>⚠ ⚠ **键里的上游地址是归一化之后的那个串**（`backend` ⇒ `backend:80`，与运行时里那个上游的名字逐字相同）—— 于是一条写 `backend`、另一条写 `backend:80` 的两条 `reverse_proxy` **共享同一格**，尽管配置里两行长得不一样。这不是缺陷而是**边界**：管理面对着的是运行时。★ `/stats` 会把三格键**原样列出来**，运维照抄即可。<br>⚠ 同一个块里写两行 `id` 是错误（`FUL-DSL-0041`），⛔ **不是「后写的赢」**；`id ""` 也是错误（`FUL-DSL-0042`）：空串正是「没写」的那一格，写它什么都没分开。<br>⚠ ⚠ **取值域是 `[A-Za-z0-9_.-]`、长度 1–64**，越界是错误（`FUL-DSL-0043`，**M2 批 P**）。★ ★ 硬的理由只有一条 —— **与兜底记号撞车**：本仓用 `<other>` / `<none>` / `<unknown>` / `<undeclared>` 表示「取不到 / 兜底」，靠的是**尖括号在真值里不可能出现**，而在这一条之前 `id <none>` 是合法的；另半条是可读性（`id` 里的换行会让 `/stats` 与日志上那一行在人眼里断成两行）。⛔ **不是指标基数**：`id` 一个字都不进指标（G126）—— ★ 一个假理由会让下一个人理直气壮地把限制放宽回去。⚠ 这是一次**收紧**：在此之前装得上的某些配置以后装不上，M4 之前没有兼容性承诺（§7）⇒ 要收就现在收最便宜。<br>⚠ **两条路各拦一次**：DSL 这条给 `FUL-DSL-0043`，而**结构化配置**那条（`POST /load`，G11 的公开入口，不经过 `fulcrum compile`）由运行时图自己再拦一遍回 400。★ 两处调的是**同一个**判据函数，⛔ 不是两份手写的平行逻辑。<br>⛔ **不自动派生**：内容哈希会让「发布时加一台机器」把刚摘掉的坏节点的覆盖顶悬空，站点内序号会让「换一下书写顺序」静默改掉寻址 —— 与 `weight` 拒绝位置式是同一条理由。<br>⚠ **跨站点不并**（第一格是站点名），**同一条 `reverse_proxy` 里把同一个地址写两遍只算一条**（那本来就是同一条上的同一台机器）。| M2 |
| `proxy_protocol` | ★ **给上游发一个 PROXY 头**，`v1` / `v2`；**省略参数就是 `v2`**（M2 批 D）。⚠ 它与 `header_up X-Forwarded-For` 解决同一件事但**层不同** —— 对**不解析 HTTP 的上游**它是唯一可用的那个。★ 枢衡自己收到过 PROXY 头时，发出去的是**那个头里的地址**（链式传递），不是自己的 | M2 |
| `weight` | **上游权重**：`weight <上游地址> <正整数>`，可写多行，**没写的上游是 1**，值域 **`[1, 65535]`**。<br>⚠ ⚠ **地址必须与 `reverse_proxy` 那一行上的 token 逐字相同** —— 这里**不做任何归一化**：写 `weight backend 3` 而上面写的是 `backend:80`，是**装载期错误**（`FUL-DSL-0038`，并把那条 `reverse_proxy` 的上游清单原样列出来）。★ 归一化住在运行时那一层，配置层再写一份「差不多的」就会分家，而分家的现场是「配置照过、权重没生效」。<br>⚠ 同一个上游写两次是错误（`FUL-DSL-0039`），⛔ **不是「后写的赢」**：那种规则下挪动一行就会静默改掉权重。<br>⛔ **`0` 不合法**（`FUL-DSL-0040`）：把一台机器摘出调度**只有一种写法** —— 管理面临时覆盖层的 `disable`。两条路做同一件事就会分家。<br>✅ **四种 `lb_policy` 全部认权重**（M2 批 N）：**先筛可用集，再在可用集上按累积权重挑**。`least_conn` 比的是 `inflight / weight`（整数交叉相乘，无浮点）。★ **被摘掉的上游连它的权重一起出局** —— 否则「按 3:1 分，而那个 3 没在跑」会让 3/4 的请求落空。<br>⚠ **落点是连发**：取「累积权重 + 游标」而不是平滑加权，所以 3:1 的落点是 `a a a b` 而**不是** `a a b a`。要平滑分布的话，这是一处函数体的事。<br>⚠ ⚠ **`ip_hash` 下改权重会让哈希映射整体错位** —— 与「一个上游掉出可用集」同一性质：会话粘性在**上游变动或权重变动**时都不保证保持。| M2 |

### `file_server` 的子块

| 子指令 | 说明 |
|---|---|
| `root` | 文档根目录。⚠ **必填**，且**必须是绝对路径**（G91）。相对路径依赖进程 cwd，而 systemd 下 cwd 是 `/`、开发机上是项目目录 —— 同一份配置会在两处指向两个地方，现场只看得到 404 |
| `index` | 目录索引文件名，可多个。**缺省 `index.html`** |
| `follow_symlinks` | `true`（**缺省**）／`false`。G87。缺省与 nginx（`disable_symlinks off`）、Caddy 一致：不做额外系统调用。写 `false` 之后按 canonicalize 校验，结果必须仍在 `root` 之内。⚠ 写法是 **`false` 不是 `off`**（见下） |
| `hide` | 命中的**路径段**回 404。**追加**在默认表之后，可写多行。G88 |
| `hide_defaults` | `true`（**缺省**）／`false`。写 `false` 关掉默认表，只用自己写的 `hide` |
| `precompressed` | **预压缩旁文件**（M2 批 I，G99）。取值同 `encode`：`gzip` / `zstd` / `br`，可多个、可写多行（**追加**）。发 `/x.css` 时，若客户端认 br 且 `/x.css.br` 在，就直接发它。<br>★ **它比现压严格更好**：旁文件本身就是被选中的那个表示 ⇒ 强 `ETag`、`Content-Length`、`Accept-Ranges` 与 Range **全都保住**，而现压那四样全掉。<br>⚠ ⚠ **旁文件比原文件旧就当它不存在** —— 这一条 nginx 与 Caddy 默认都**不做**。理由：一个改了 `x.css` 却忘了重新生成 `x.css.br` 的部署，只会让**支持 br 的那部分用户**拿到旧内容，不报任何错、日志里一行都没有，而开发者自己的浏览器还很可能拿到新的 |

（`browse` 是行内标志，不在子块里：`file_server browse { root /srv/www }`。）

**默认 hide 清单**（非空，装载时会逐条打出来）：
`.git` · `.env` · `.svn` · `.hg` · `.bzr` · `.DS_Store`

- 按**路径段**匹配：`/x/.git/config` 命中，而 `.gitlab-ci.yml` **不会**被 `.git` 命中。
- 命中回 **404 不是 403** —— 403 等于确认「这个文件在」，那是一次信息泄漏。
- ★ `.well-known/` **不受影响**：这里不按 `.` 一刀切，它只是一个普通目录。
  ⚠ 若按「点开头一律 404」做，用户的静态站会**把自己的证书签发挡掉**
  （HTTP-01 的挑战路径就在 `.well-known/acme-challenge/` 下），
  而现场看到的只是「CA 说验不过」。

⚠ ⚠ **两条布尔只认 `true` / `false`**，明确拒绝 `yes/no/on/off`
（与 `tls_insecure_skip_verify` 同一条口径）。★ 代价认下：从 nginx
（`disable_symlinks off`）迁过来的人会下意识写 `off`，由诊断的 did-you-mean 接住 ——
换的是**一套 DSL 只有一种布尔写法**。

**这一批做到哪**（G89）：发文件 · 目录索引 · 目录不带尾斜杠 **301** 到带斜杠
（查询串保留）· `browse` 目录列表 · `ETag` / `Last-Modified` /
`If-None-Match` / `If-Modified-Since` → **304** · **单段** `Range` 与 `If-Range`。

**明确不做**：多段 `multipart/byteranges`（回 **200 全量**，RFC 9110 允许忽略 `Range`）。
方法只认 `GET` / `HEAD`，其余 **405** 且带 `Allow`。

> ✅ ✅ **预压缩旁文件在 M2 批 I 做完** —— 见上表的 `precompressed`。
> ⚠ 这里原本写的是「不做，因为 `encode` 本身还在 `UNWIRED` 里，先做旁文件会让
> 『压缩』有两个互不知道的实现」。★ 那条理由是对的，而它**成立的前提在批 I 消失了**：
> `encode` 接线之后两者是同一件事的两半 —— 有旁文件用旁文件、没有才现压，
> 而「已经压过的不再压一遍」由压缩层自己（看见 `Content-Encoding` 就放行）与
> `file_server`（选中旁文件就把 encoder 丢掉）**两处各挡一道**。

`Content-Type` 由**自带的一张约 60 条小表**决定，查不到就是
`application/octet-stream`（G90：一个只需要查表的能力，不值得为它抬依赖面）。

## 4.2 中间件类

| 指令 | 形式 | 状态 |
|---|---|---|
| `header` | `header [matcher] [+-]<name> [value]` | **M1 自研** |
| `rewrite` | `rewrite [matcher] <to>` — 内部改写，不发重定向 | **M1 自研** |
| `encode` | `encode gzip zstd br` | **M2 自研**（批 I；压缩本体用 fork 里那份，G100）|
| `cache` | `cache [matcher] { ttl … }` | **M2 自研**（语义层与内存后端＝批 G，磁盘后端＝批 H）|

### `cache` 的子块

| 子指令 | 说明 |
|---|---|
| `ttl` | ⚠ ⚠ **兜底**新鲜度，**不是覆盖**（G96）：只有上游**没给** `Cache-Control: max-age` / `s-maxage` / `Expires` 时才用它。上游给了就听上游的。★ 不写它 ⇒ 上游没说新鲜度的响应**不缓存**。<br>★ 取兜底而不是覆盖的理由：覆盖语义会让一个带 `no-store` 的响应也被存下来 —— 而那是「偶尔给错内容」里最贵的一种。⚠ 代价认下：从 nginx `proxy_cache_valid` 迁过来的人会发现它不覆盖 |
| `max_size` | **单条目**大小上限。超过它的响应**不进缓存**（照发给客户端）。缺省 8MB |
| `capacity` | **整个缓存**的容量上限，达到就按 **LRU** 淘汰。缺省 256MB。⚠ 它是必需的而不是可选的 —— 一个没有上限的内存缓存就是一处内存泄漏，而那种泄漏的现场是「跑几天之后被 OOM 杀掉」，与缓存本身看不出关系。★ 写了 `disk` 时它是**磁盘**预算，不写时是**内存**预算 —— 同一条指令、两种介质，生效值与介质都在装载日志里 |
| `disk` | **磁盘后端**的根目录（**批 H**，G83/G84）。写了它 ⇒ 缓存落盘、进程重启后**还在**；不写 ⇒ 内存后端，重启即空。必须是**绝对路径**（`FUL-DSL-0033`）。<br>⚠ ⚠ **缓存后端是进程级的**：多个 `cache` 块写了**不同**的 `disk`（含「一个写了、一个没写」）是编译期错误 `FUL-DSL-0035` —— 两个不同的值里必有一个是「你以为生效、其实没有」的。★ 与 `capacity` 处置不同是因为代价不同：容量取大一点不会让任何站点拿不到东西，目录取一个会让另一个站点的缓存整个落在别处<br>★ 名字取 `disk` 而不是 `path`：`path` 在本 DSL 里已经是**请求路径**（匹配器与 `{path}` 占位符） |

**做到哪**（G97）：可缓存性判定 · 新鲜度 · 缓存键 · `Vary` · 条件重验证
（`If-None-Match` / `If-Modified-Since` 发给上游，收到 **304 只更新元数据、不动 body**）·
**上游响应头里的全套 `Cache-Control` 指令**（`no-store` / `no-cache`（两种形态）/
`private`（两种形态）/ `public` / `max-age` / `s-maxage` / `must-revalidate` /
`proxy-revalidate` / `immutable` / `no-transform`）· **防惊群** · `POST /purge`
· **磁盘后端**（批 H）。

**明确不做**：`stale-while-revalidate` / `stale-if-error`（解析了但**不施加**）·
缓存 `HEAD` · 缓存 `206` 部分响应。

### 磁盘后端做成什么形状（G83 / G84）

| | |
|---|---|
| 布局 | 缓存键 hash 的**两级分片目录**；meta 与 body **两类文件**；`tmp` 后 `rename` 原子落地 |
| 重验证 | **只改 meta 不动 body** —— 这正是 meta 与 body 分开的理由 |
| 启动 | **不扫盘**：读时按键算出文件名直接开 ⇒ **重启之后第一个请求就能命中**；淘汰索引走 save/load，后台每秒走一个一级分片目录渐进重建 |
| 崩溃恢复 | 读时校验（body 长度与 meta 对不上就**即丢即删**）；后台清理收掉没人认领的 body 与坏掉的 meta |
| 目录用不了 | ★ **关掉缓存、照常转发**（不是退回内存 —— 按磁盘写的 `capacity` 会变成内存预算而 OOM；也不是拒绝启动 —— 换代时那等于服务整体中断）。装载日志有一行 `error`，运行时 `X-Fulcrum-Cache` 那个头不再出现 |

⚠ **代价写在明处**：淘汰索引与盘之间有个**最终一致**的窗口 —— 刚重启时占用算得偏小，
于是淘汰比稳态晚一点触发。★ 而**命中不受影响**，因为读路径根本不看索引。

★ ★ **我们是共享缓存**，这一句改变好几处判断，其中最贵的一条是：
**带 `Authorization` 的请求，其响应默认不可缓存**（RFC 9111 §3.5），
除非响应明确写了 `public` / `s-maxage` / `must-revalidate`。
⚠ 漏了它就是**把一个人的私有页面发给下一个人**，而不会有任何报错。

★ 命中的响应带 `Age` 与 `X-Fulcrum-Cache` 两个头 ——
⚠ `Age` 是 RFC 9111 §5.1 要求的：下游若还有一层缓存，它要拿 `Age` 算自己的新鲜度；
不发的话同一份内容会被一路放大到两倍寿命。

`X-Fulcrum-Cache` 的取值：内存后端是 `HIT` / `REVALIDATED`，
磁盘后端是 `HIT-DISK` / `REVALIDATED-DISK`。
★ 后缀说的是**这个进程真的挑中了哪个后端**，不是配置里写了什么 ——
⚠ 「配了 `disk` 而目录用不了」时缓存是关掉的，这个头**一个都不会出现**。

⚠ **缓存只裹 `reverse_proxy`**：`respond` / `redir` 没有上游可省，
而 `file_server` 的字节已经在本机磁盘上、再存一份内存是净亏。

## 4.3 容器与结构

| 指令 | 说明 |
|---|---|
| `route { … }` | ★ **保序容器**（G49 的逃生口），块内按书写顺序 |
| `handle [matcher] { … }` | **互斥容器**：多个 `handle` 里只有第一个匹配的会执行 |
| `handle_errors { … }` | 错误页（G63）。块内可用 `{status}` 占位符 |

## 4.4 站点级

| 指令 | 形式 | 状态 |
|---|---|---|
| `tls` | `tls`（自动，默认）／`tls <cert> <key>`／`tls internal`（自签）／`tls { on_demand … }` | **M1 自研** |
| `log` | `log { output … }` — ⚠ **字段清单与格式是 D7（M2）**，M1 只给最小可用形态 | M1 部分 |

### `tls` 的子块

| 子指令 | 说明 |
|---|---|
| `on_demand` | 握手期按 SNI 触发签发（G12）。⚠ ⚠ **只到配置层为止**：还欠对 `ask` 的准入调用、并发闸门与失败缓存 —— 它在 `fulcrum_runtime::UNWIRED` 里登记着，装载时会打出来 |
| `ask` | ★ **准入端点。G15：开了 `on_demand` 却没配它，拒绝启动**——这里在编译期就红 |
| `dns` | DNS-01 用哪家（G57：`cloudflare` / `dnspod` 原生，其余走 `exec` hook）|
| `resolvers` | 校验 TXT 可见性时问哪些**权威 NS**。★ G58：**要轮询确认，绝不能只 sleep 一个固定秒数** |
| `zones` | ★ 这份 DNS 凭据被**声明**覆盖哪些 zone。**G59 第 3 条：原生供应商必填**，超出声明范围一律拒绝 |

### DNS-01 怎么写（G57 / G58）

```text
*.example.com {
    tls {
        dns exec /etc/fulcrum/dns-hook.sh
        resolvers ns1.example.net:53 ns2.example.net:53
    }
    respond 200
}
```

★ ★ **`dns` 与 `resolvers` 必须成对出现，否则编译期就红** —— 形状照 G15
（`on_demand` 没配 `ask` 就拒绝启动）。理由是 G58 那条硬约束：
确认 TXT 可见只能靠**真去问权威 NS**，少了 `resolvers`，实现要么退回固定 sleep
（G58 明确禁止），要么在签发中途才报错——而那时已经在 CA 那边开了一张订单、
并且往 DNS 上写了一条记录。

★ **不带端口就补 `:53`**。写 **IPv4 字面量或主机名都行**，而两者的差别只在**什么时候解析**：

| 写法 | 什么时候变成地址 |
|---|---|
| `1.12.0.1:53` | 就是它 |
| `drummer.dnspod.net` | ★ **每次签发那一刻**解析一次，解出几个地址就问几个 |

⚠ ⚠ **主机名不会在启动时被钉成 IP，这是有意的。** 钉住等于赌「这个名字对应的地址永远不变」，
而 `resolvers` 指的恰恰是 anycast 权威 —— 实测 `drummer.dnspod.net` 一次解出 **6 个地址**（含 IPv6），
而两小时前手抄进配置的只有 3 个。★ 现场表现会极难查：**证书签不下来，而配置、凭据、DNS 记录全对**。

★ ★ **一个名字解出几个地址就问几个**，不是挑第一个：那是几台**各自独立**的权威节点，
而 TXT 是逐节点同步过去的。只问第一台，就会把「这一台已经有了」当成「全网都有了」——
 真机上正是这个形状：本地判定可见、CA 那边仍判 `Invalid`，43 秒后重试才成。

⚠ **写得不对是编译期错误**（`FUL-DSL-0029`），不是装载时一行日志：
端口不在 1–65535、主机名里有非法字符、IPv6 字面量（M1 不支持）都在 `validate` 就红。
★ 而「这个名字现在解析得出来吗」**不在编译期判** —— 那要网络，
一次 DNS 抖动不该让一份没改过的配置突然编不过。解析失败会变成一次**响亮的签发失败 + 退避**。

★ ★ **凭据不写在这里**（G59 第 1 条）。DSL 是要被 diff、被贴进 issue、
被版本控制的东西——**凭据只从环境变量或文件读**。
exec hook 自己去拿；原生供应商则在 DSL 里给出**来源**，见下。

#### 原生 Cloudflare / DNSPod 怎么写（G57 / G59）

```text
*.example.net {
    tls {
        dns cloudflare env:CF_API_TOKEN
        zones example.net
        resolvers west.ns.cloudflare.com:53 arely.ns.cloudflare.com:53
    }
    respond 200
}
```

`dns <cloudflare|dnspod> <凭据>` 的第二个参数有三种写法：

| 写法 | 含义 | 它是秘密吗 |
|---|---|---|
| `env:名字` | 从环境变量读 | ❌ 是**指针**，配置里看不到值 |
| `file:路径` | 从文件读（`trim`，空的当成没有凭据）| ❌ 同上 |
| 直接写值 | **凭据本身**（Caddy 形状）| ✅ **是** —— 见下 |
| `literal:<值>` | 同上，用于**值里带冒号**的场合 | ✅ |

## ⚠ ⚠ ⚠ 写了字面量，这份配置文件就是秘密了

★ ★ 允许内联的代价不是「多一种写法」，而是**配置文件的性质变了**。
枢衡里有四条路会把配置原样吐出来，所以内联凭据之后这四条都必须跟着变：

| 路 | 变成什么 |
|---|---|
| `fulcrum compile` | **默认脱敏**（凭据变成 `«已脱敏»`）；要真值得显式 `--with-secrets`，而且它会在 stderr 上说一声 |
| `POST /load` 的载荷 | 同上 —— ⚠ 拿默认产物去 load 会被**明确拒绝**，而不是把 `«已脱敏»` 当凭据发给 CA |
| 诊断（出错那一行会被原样打出来）| 由上面那条脱敏兜住 |
| `Debug` / 日志 | `Secret` 的 `Debug`/`Display` 默认脱敏 |

★ **判据不是「我们记得在这四处脱敏」，而是默认就不出真值** ——
一条要在 N 个地方记住的规则，迟早会在其中一个地方被忘掉。

### ★ 装载期的权限门

只要配置里出现字面量凭据，装载时就检查这份文件**别人读不读得到**：

| 情况 | 处置 |
|---|---|
| 没有字面量凭据 | **一个字都不查**（不去管别人怎么放一份没有秘密的配置）|
| 有，且 `o` 位有任何权限（如 `0644`）| **拒绝启动**，并告诉你 `chmod 640` 怎么改 |
| 有，`0640 root:<服务组>` | 放行 —— 这是正当形状：root 拥有、服务只读 |

⚠ 不要求 `0600`：那会**逼人把配置交给服务用户拥有**，而配置本该由 root 管。
★ 一条把人推向更差实践的规则，比没有规则更糟。

### ⚠ 打错的来源前缀会被拦下（`FUL-DSL-0031`）

既然不写前缀就是值本身，那么 `fil:/path`、`ENV:NAME` 这类**打错的前缀**
会被当成凭据发给对端 —— 现场是「凭据不对」，而真正的原因是打错了几个字母。
⇒ 长得像来源前缀、而那个前缀不认识 ⇒ **编译期报错**。
★ 白名单那条老理由（「猜错的那一次恰恰就是真 token 被放行的那一次」）没有失效，
它只是**换了落点**：从「拦字面量」变成「拦打错的前缀」。

★ ★ **`zones` 对原生供应商是必填**（G59 第 3 条）。它声明「这份凭据被允许动哪些 zone」，
签发时记录名不落在其中就**直接拒绝，一个 API 请求都不发**。

> ⚠ 它不等于「凭据实际能干什么」：DNSPod 的 token 是**账号级**的，
> 覆盖该账号下的全部域名，而且**没有可问出范围的端点**。
> 声明的价值在于——**越权那一刻是枢衡自己拒绝的，而且拒绝的理由在配置里看得见**。
>
> ★ 判据按**标签边界**判，不是后缀：声明 `example.net` **不会**放行 `evilexample.net`。
> 同时声明父子 zone 时取最长的那个。

★ **Cloudflare 还会在启动时被真校验一次**（G59 第 2 条）：对**声明的每一个 `zones`** 查一次 id
（`GET /zones?name=…`，与签发路径上的第一步同一个请求形状）——
凭据读不出来、或者对端说它不可用，**拒绝启动**——形状照 G15，错误在启动时暴露。
⚠ 而**校验请求发不出去**（网络不通）时只打一条 error 继续跑，不拒绝启动：
一次网络抖动不该让整台机器上**所有**站点都起不来，包括那些用静态证书的。
★ 这是一处知情的取舍，不是遗漏。DNSPod 只能验「凭据能用」（`Info.Version`），验不了范围。

#### exec hook 的调用约定

```text
<程序> set   <记录名> <值>     # 挂上一条 TXT
<程序> clear <记录名> <值>     # 摘掉
```

退出码非零即视为失败，stdout/stderr 会被截断后带进错误信息。

⚠ **它是一个新的攻击面**，所以：**不经 shell 解释**（三个参数各是一个独立 argv，
`a.com; rm -rf /` 这种域名只是普通字节）、**有超时且到点就杀**、
**输出有上限**、以服务自己的用户身份运行、不做任何提权。

★ 记录名由枢衡算好给你，通配符已经剥掉前缀：
`*.example.com` 的挑战记录是 `_acme-challenge.example.com`
（RFC 8555 §8.4，**不是** `_acme-challenge.*.example.com`）。

✅ **原生 `cloudflare` / `dnspod` 已接线**（连同 G59 的启动时凭据校验），
★ 并且**两家都在真域名上签过生产证书**：`*.example.com` 走 DNSPod、
`*.example.net` 走 Cloudflare（批 19）。
⚠ 两条只有真对端才会暴露的口径，写在这里免得下一个人再撞：
**DNSPod 免费版 TTL 下限是 600**（写死 60 会让每一张证书都签不下来）；
**Cloudflare 要 `Zone:Read` + `DNS:Edit` 两项**权限，而官方「Edit zone DNS」模板只给后者。

### `log` 的子块

✅ **全部接线**（M2 批 L 第 **②** 步：固定集；第 **③** 步：白名单头 + TLS 信息；
D7 由 G113 + G114 结案）。
★ **字段清单与格式的权威是 [观测](/architecture/observability.md)**，本节只说配置面。

| 子指令 | 说明 |
|---|---|
| `output` | `stderr`（默认，进 journal）或 `file <绝对路径>`。★ ★ 文件**在装载时就打开**，打不开是**硬错误**（`serve` 起不来 / `POST /load` 回 400 且旧配置一个字节没动）—— ⚠ 一个用来「出了事你能知道」的东西，自己坏掉时必须有人知道。⚠ 必须绝对路径，理由与 `cache { disk }`（G91）逐字相同 |
| `level` | **阈值**，不是「这一行的级别」：`warn` 只记 4xx/5xx，`error` 只记 5xx。⚠ 对访问日志 **`debug` 与 `info` 等价**（都记全部）—— 保留 `debug` 只因为它本来就在取值表里，而**多一个取值不多一种行为** |
| `headers` | 写成 `headers <名字…>`（至少一个）。**请求头白名单**：⚠ ⚠ 默认**一个头都不记** —— 不写这一行就是不记，没有「记几个常用的」这种中间态 |
| `resp_headers` | 写成 `resp_headers <名字…>`。**响应头白名单**。★ 取的是**最终**响应头（`header` 那一步之后写出去的），不是上游给的那一份 |

⚠ ⚠ **每一行自己的 `level` 字段是按状态码派生的**（`<400` info · `4xx` warn · `5xx` error），
与上面那个阈值**是两件事**：前者给日志的消费方看，后者给运维用来关掉噪音。
★ 合成一个的话，「只记错误」就没法表达了。

#### ⚠ ⚠ ⚠ 白名单里的四个名字是编译期错误（`FUL-DSL-0036`）

`Authorization` · `Cookie` · `Set-Cookie` · `Proxy-Authorization`
写进任一白名单 ⇒ **配置装不上**（大小写不敏感）。

★ ★ 取「编译期拒绝」而不是「运行时脱敏」：后者要求脱敏表跟得上每一个新的敏感头名，
而**漏一个就是一次静默泄漏**；前者的失效形态是「配置装不上」，当场可见。
⚠ **两条路各拦一次**：DSL 这条给 `FUL-DSL-0036`，而**结构化配置**那条
（`POST /load`，G11 的公开入口，不经过 `fulcrum compile`）由运行时图自己再拦一遍回 400。

⚠ 白名单里的名字还必须是**合法 HTTP 头名**（RFC 9110 的 `token`），否则也装不上 ——
★ 理由是「查不到」与「这条请求上没有这个头」在日志里长得一模一样，
一个拼错的名字会**静静地什么都不记**。

⚠ ⚠ **没有站点匹配的请求（421）记不进访问日志**：`log` 是站点块内的指令，
而那条请求按定义不属于任何站点。★ 那是 **D26**（✅ 已由 **G118** 结案 —— 给
`no_site_match` 一个计数器），不是遗漏。
⚠ **走 HTTP/3 的请求只有三格 TLS 信息**（`tls_cipher` 拿不到）——
✅ D27 已结案（G128，落点 fork 改动 14），理由见
[观测](/architecture/observability.md) 那一节。

## 4.5 顶层非站点块（M2）

L4 面（§6.1）不是站点块内的指令，它有自己的顶层块：

```text
l4 {
    tcp :3306 {
        proxy 10.0.0.5:3306
    }
    udp :53 {
        proxy 10.0.0.6:53
    }

    # SNI / ALPN 分流（M2 批 C）：**不终止 TLS**，只看一眼 ClientHello 再决定送给谁
    tcp :443 {
        sni api.example.com {
            proxy 10.0.0.1:8443
        }
        sni *.internal.example.com {
            proxy 10.0.0.2:8443
        }
        alpn h2 {
            proxy 10.0.0.3:8443
        }
        proxy 10.0.0.9:8443          # 兜底：没命中、不是 TLS、或看不懂的 ClientHello
    }
}
```

## SNI / ALPN 分流（批 C）

| 规则 | 语义 |
|---|---|
| `sni <名字…>` | ClientHello 的 `server_name`。**精确**或 `*.example.com`（★ **只吃一层**，与站点索引、证书解析**共用同一份实现**，G66）。⚠ 大小写不敏感 |
| `alpn <协议…>` | ClientHello 的 ALPN 清单，**逐字节相等**、任意一条命中即算命中。⚠ **不是前缀匹配**：`h2` 与 `h2c` 是两个协议 |
| 裸 `proxy` | **兜底**。没写就表示「只服务我认得的那几个名字」，其余连接**直接关闭**并记一行 |

★ **同一条里写多个值是 OR**（与站点块里的匹配器同一条口径）；
★ ★ **规则按书写顺序匹配，第一个命中即用** —— L4 没有那张执行顺序表
（它是给中间件排序的），所以这里的顺序**就是你写的顺序**，与 `route { … }` 同源。

⚠ ⚠ **这是「看一眼」，不是「终止 TLS」**：枢衡读走的那几个字节会**原样重放**给上游，
上游拿到的是一条完整的、从第一个字节开始的 TLS 流。★ 这条由门禁逐字节比对
（`tests/l4/run.sh`），因为它错了的现场表现是「TLS 偶尔握手失败」，而枢衡这边一切正常。

⚠ **能不能分流，只取决于能不能读出 SNI**。★ 换到 BoringSSL（G104）之后这一条变宽了：
它的早回调在几乎全部 ClientHello 校验**之前**触发，于是一个完整 TLS 栈会拒绝的 hello
（例如缺 `signature_algorithms` 扩展）照样按 SNI 分流。
★ 读不出 SNI 的连接**走兜底**，不是被关掉：枢衡不替上游拒绝一个上游自己也许能处理的客户端。

⚠ **`udp` 上不能写 `sni` / `alpn`，而这不是「以后再做」，是做不到**：
UDP 上没有 TLS ClientHello，QUIC 的 Initial 是**加密的**。写了是编译期错误，
且诊断会说出这个理由 —— 一条只说「不支持」的诊断会让人以为等等就有了。

★ 看 ClientHello 有**两个上限**，写在代码里也写在这里：最多等 **3 秒**、最多缓存 **16 KiB**；
超了就按「不是 TLS」走兜底。⚠ 它与 TCP 那条「有意不设空闲超时」不冲突：
那说的是**已经接上上游**之后，而这一段连上游都还没选出来。

状态（**M2 批 A**）：

| | 现在怎样 |
|---|---|
| `tcp` | ✅ **枢衡自己转发**（批 A）：自建监听器 + 参与 socket 移交；多个 `proxy` 轮询，与 `reverse_proxy` **共用同一套挑上游的实现**；★ 建连阶段会自动换下一个上游。**批 C** 起还能按 `sni` / `alpn` 分流（见下） |
| `udp` | ✅ **枢衡自己转发**（批 B）：按客户端地址维护会话，**空闲 60 秒回收**、每个监听器最多 **1024 条并发会话**（⚠ UDP 源地址可伪造，这两条是防 fd 被打光的）；★ 停机信号一到就**停止收包**，否则老一代会抢走新一代的数据报 |

⚠ **UDP 与 TCP 有三处语义差别**，写在 `crates/fulcrum-server/src/l4.rs` 的 UDP 那一节：
会话边界要自己维护、**空闲超时必须有**（UDP 没有 FIN）、停机时要停 `recv_from`。
★ 还有一条：UDP 的 `connect` **不是握手**，它证明不了上游活着 ⇒
TCP 那边「建连阶段换上游」的做法在 UDP 上**没有对应物**，挑一次就用它。

⚠ **上游必须写明端口**（`10.0.0.5:3306`）：HTTP 那边缺端口能按 scheme 补 80/443，
一个裸 TCP 监听器没有 scheme，补不了。

⚠ **监听地址在启动时绑定**，与 HTTP 端口同一条限制：`POST /load` 换不了它（会回 409），
换要走 `systemctl reload`。★ 但 `proxy` 后面的**上游随时可以改** —— 换上游不经过 bind。

★ **没有空闲超时，这是有意的**：L4 的典型对象是数据库连接，空闲几小时是正常的，
而一个「看起来安全」的 30 秒超时会让枢衡去杀一条两端都认为健康的连接 ——
现场表现是「数据库偶尔断线」。空闲由两端自己管。

✅ **SNI / ALPN 分流（批 C）落地**，写法见上。

## PROXY protocol（批 D）

§6.1 承诺的最后一样。**收与发都做**，`tcp` 块里两条独立的指令：

```text
l4 {
    tcp :5432 {
        proxy_protocol_from 10.0.0.0/8    # 收：信任这些来源发来的头
        proxy_protocol                    # 发：给上游发一个（省略参数＝ v2）
        proxy 10.0.0.7:5432
    }
}
```

| 指令 | 语义 |
|---|---|
| `proxy_protocol_from <网段…>` | **收**。★ **不在清单里就一个字节都不读** —— 口径与理由见 §二那一节 |
| `proxy_protocol [v1\|v2]` | **发**。省略参数＝ **`v2`**（owner 拍板）|

★ ★ **收与发是两件独立的事，不是一个开关的两半**：只收不发、只发不收、
收了再发（**链式传递**：上游看到的仍是最初那个客户端）三种都是真实用法。

⚠ ⚠ ⚠ **写了 `proxy_protocol_from` 之后，清单内的来源不发头会被关掉连接。**
这一条会让人意外，所以说在明处：`proxy_protocol_from 10.0.0.0/8` 这句话的意思是
**「这个网段的流量是经代理来的」**，⇒ 那个网段里出现一条不带头的连接本身就是异常。
★ 取「必须发」而不是「发了就用、没发就算了」的理由是安全上的：若允许清单内的来源
**选择性地**不发头，它就能让枢衡改用 socket 对端 —— 而那个地址正是 LB 自己，
于是一条 `remote_ip 10.0.0.0/8` 规则会**命中它**。
⚠ **代价**：清单配宽了（比如整个 `10.0.0.0/8`），那个网段里所有不发头的正常连接都会被拒。
★ 这与 HAProxy 的 `accept-proxy`、nginx 的 `listen … proxy_protocol` 是同一条语义，
只是枢衡多了一层**来源限定**。

★ 两条时间上限：等 PROXY 头最多 **3 秒**。⚠ 它与「看 ClientHello」那 3 秒是**两段**：
一条既收 PROXY 头、又配了 `sni` 分流的连接，最坏要 **6 秒**才选得出上游。

⚠ ⚠ ★ **上面这两个数只管 `l4` 那半边。HTTP 面（全局 `proxy_protocol_from`）的口径不一样，
而这个不一样是有意的**：HTTP 面那段读发生在 `handshake()` 里，而上游**已经**把整个
`handshake()` 包在一个 **60 秒**的超时里、并且是 per-connection spawn 的。
⇒ 再加一个自己的超时，就是多一个要与它同步的数字。★ 它有的是另一道保证：
缓冲区**硬上界 4096 字节**（那是「这个循环一定会停」的兜底，真正的协议上界由解析器自己给）。
⚠ 别把「L4 是 3 秒」读成「HTTP 面也是 3 秒」—— 两半边在这一点上从来没有对齐过。

⚠ ⚠ **`udp` 上写这两条是编译期错误，而这不是「以后再做」**：
PROXY protocol 是**面向连接**的 —— 头在连接开头发一次。UDP 上没有「连接开头」，
每个数据报都是独立的：「只发一次」没有落点，「每个都发」不是这个协议规定的东西。
★ 与 `sni` / `alpn` 在 `udp` 上那条同一条纪律，**诊断都要说出为什么**。

原文（M1，G60）：**解析得过，编译成回落**。保留在这里，因为它说明这一格是**什么时候、
因为哪一批**变的 —— 而不是看起来一直如此。
★ 至此 `l4` **不再产生任何回落标记**，`L4Config` 里那个 `fallback` 字段也整个删掉了：
⚠ 一个恒为 `None` 的字段不是「保守」，它是**一句会被当真的假话** ——
`compile` / `plan` 的产物是公开契约，读的人会以为那条路还在。

# 五、匹配器（G50）

**复杂条件一律走命名块；行内只允许路径。**

```text
@admin {
    path      /admin/*
    remote_ip 10.0.0.0/8
    method    POST PUT DELETE
}
handle @admin { … }

reverse_proxy /api/* backend:8080      # 行内简写：只能是路径
rewrite       * /new/x                 # ★ `*` 显式占住匹配器位
```

★ ★ **`*` 是必需的一条逃生口**（照 Caddy）：规则是「第一个以 `/` 开头的参数就是匹配器」，
而 `rewrite /new/x` 里那个 `/new/x` 其实是**目标**。没有 `*`，这条最自然的写法就是死胡同。
⚠ 写错时诊断会直接告诉你改成 `rewrite * /new/x`，不会只丢一句「参数不对」。

| 条件 | 说明 |
|---|---|
| `path` | 路径，支持 `*` 通配 |
| `path_regexp [name] <re>` | 正则；命名捕获组可由 `{path.N}` 引用 |
| `host` | Host 头 |
| `method` | 请求方法（可多个）|
| `header <name> [value]` | 请求头存在 / 等于 |
| `query <k>=<v>` | 查询参数 |
| `remote_ip <cidr…>` | 客户端 IP。★ 取值口径见[安全基线](/platform/security-baseline.md)——**不能取 XFF 最左项** |
| `not { … }` | 取反 |

行内匹配器位只认三种写法：`@name`、以 `/` 开头的路径、以及 `*`（全部匹配）。

★ 同一 `@name` 块内**多条件是 AND**；同一条件写多个值是 OR。

# 六、占位符（G61：小而固定，无表达式、无函数、无条件）

**只有下面这些，文档列全。** ★ DSL 一旦长出图灵完备的表达式层，
它就变成一门没人测试的编程语言，而错误提示会跟着失控。

| 占位符 | 含义 |
|---|---|
| `{host}` | 请求的 Host |
| `{uri}` | 完整 URI（含查询串）|
| `{path}` | 路径部分 |
| `{query}` | 查询串（不含 `?`）|
| `{method}` | 请求方法 |
| `{scheme}` | `http` / `https` |
| `{remote_ip}` | 客户端 IP |
| `{remote_port}` | 客户端端口 |
| `{header.<Name>}` | 请求头 |
| `{resp_header.<Name>}` | 响应头（仅 `handle_errors` 与响应侧指令可用）|
| `{path.<N>}` | `path_regexp` 的第 N 个捕获组 |
| `{status}` | 响应状态码（仅 `handle_errors` 可用）|
| `{upstream}` | 本次选中的上游地址（仅响应侧可用）|
| `{time}` | 请求开始时间（RFC 3339）|

★ **用在不可用的位置是编译错误，不是空串。** 空串会让 `handle_errors` 之外误用
`{status}` 的配置**看起来能跑**，而输出里少一段——那正是本项目反复抓的那种无声失败。

# 七、类型与字面量

| 类型 | 写法 | 说明 |
|---|---|---|
| 时长 | `5s` `1m` `2h` `500ms` | ★ **裸数字是错误**，不做默认单位 |
| 大小 | `10MB` `1GiB` | 十进制与二进制前缀都认，含义按 IEC |
| 布尔 | `true` / `false` | ★ **只认这两个**——不接受 `yes/no/on/off`，避开 YAML `no → false` 那类坑 |
| 字符串 | 裸词或 `"…"` | 含空格、`{`、`#` 时必须加引号 |
| 注释 | `#` 到行尾 | 只能整行或行尾，不能在引号内 |

# 八、默认值（G63）——★ 默认值本身就是契约

| 情形 | 默认响应 |
|---|---|
| **无站点匹配** | **421 Misdirected Request** |
| 站点内无路由匹配 | 404 |
| 上游全部不健康 | 502 |

★ **无站点匹配返回 421 而不是静默交给某个站点**：后者是 nginx `default_server`
那类行为的温床——请求被交给一个用户没打算让它去的地方，而且没有任何提示。

`handle_errors { … }` 可覆盖，块内可用 `{status}`。

# 九、错误提示规范（G51）

**一次报全 + 稳定错误码。** 每条诊断至少包含：

```text
error[FUL-DSL-0007]: unknown directive `reverse-proxy`
  --> /etc/fulcrum/Fulcrumfile:12:5
   |
12 |     reverse-proxy 127.0.0.1:3000
   |     ^^^^^^^^^^^^^ 未知指令
   |
   = help: 你是不是想写 `reverse_proxy`？
   = note: 全部指令见 docs/architecture/dsl-reference.md §4
```

- **行列号 + 源码片段 + caret**，缺一不可；
- **错误码 `FUL-DSL-NNNN` 稳定**，可被文档与自动化引用（⚠ 一旦发出就不能改含义，与 D9 相邻）；
- 尽量**错误恢复**，把能报的一次报完——依据是设计原则第 4 条「配置变更是事务」。

★ **G49 之下有一类专属诊断**：当执行顺序与书写顺序不同并造成了意外，
诊断必须说出「它实际跑在第几步」，否则用户只能去背 §三那张表。

# 十、最容易在哪做错

1. ★ ★ ★ **加了指令却没在 §三的顺序表里给它位置。** 见 §三第 2 条——
   **做成编译期穷尽性检查，让它编不过。**
2. ★ **把占位符在不可用位置解析成空串。** 必须是编译错误（§六）。
3. ★ **给 `remote_ip` 取 XFF 的最左项。** 那是**客户端可伪造**的；口径见[安全基线](/platform/security-baseline.md)。
4. **以为裸写 `file_server` 还能编过。** M2 批 F 起 **`root` 必填且必须绝对**（G91）——
   ⚠ 这一条推翻了它在 M1–批 E 期间的行为（那时它编译成回落路由，由装载日志逐条列出）。
   ★ 旧行为写在这里不是历史癖好：**照着旧文档抄的配置现在会编不过**，
   而报错指的是 `root`，不是「file_server 变了」。
5. **给 `import` 留后门。** G62 明确 M1 不做，因为它会一次性引入跨文件错误定位、
   循环引用与相对路径三件事，**恰好都打在 G51 刚把标准定高的那个面上**。
