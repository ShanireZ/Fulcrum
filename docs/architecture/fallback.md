# ✅ 它接线了（G79）

在此之前，该走回落的请求一律回 **501**（一个诚实的中间态）。现在：

| 全局块里 | 该走回落的请求 |
|---|---|
| 没写 `fallback_nginx` | **501** —— 你没告诉我后端在哪 |
| 写了，后端连得上 | **转发过去**（+1 跳）|
| 写了，后端连不上 | **502**（`all_upstreams_down`）|

★ ★ **501 与 502 有意不合并**：合并之后，一次配置遗漏与一次后端故障
在现场长得一模一样。三个方向各有一条端到端判据（`tests/serve/run.sh`）。

★ ★ ★ **「薄转发」是用「共用同一段代码」落实的**：回落目标就是一个普通的
`ProxyTarget`，走的是与 `reverse_proxy` **完全同一段**转发函数。
能力翻译、配置语义映射、统一两家行为差异 —— 这三件事因此**做不到**，
而不是靠自觉不去做。

⚠ `fallback_caddy` 收得进 DSL，但 **HTTP 执行链上没有任何指令指向 caddy**：
只有 `l4` 回落 caddy，而 l4 整条还没接线。这件事由一道结构门盯着
（`crates/fulcrum-runtime/tests/fallback.rs` 的
`http_链上目前只有_nginx_一种回落目标`），哪天有指令指向 caddy 了它会红。

⚠ **回落地址指回枢衡自己会被拒绝构建**（`fulcrum validate` 就报）：那是无限循环，
而它的现场表现只是源源不断的正常转发记录。判据取得很窄 —— 主机是本机形式
**且**端口在本进程监听集里，两条同时成立才判。宁可漏报也不许误报：
一次误报会让一份合法配置**起不到**。

# 它是什么

自研某块能力尚未完成时，枢衡把该类请求**转发给成熟引擎**：

| 能力 | 回落给 |
|---|---|
| 静态文件、HTTP 缓存 | **Nginx** |
| 其余未完成能力 | **Caddy** |

★ **回落是时间轴上的临时顶班**（G9），不是架构层次。某块自研完成即拆除，**1.0 时回落代码归零**。

# 四条约束（防止它长成第二个产品）

1. ★ **只做薄转发。** 不做能力翻译，不做配置语义映射，**不试图统一两家的行为差异**。
2. **边界显式。** 哪些请求走回落，必须在配置中可见、在 stats 中计数、在计划输出中**标出额外跳数**。
3. ★ **一块自研完成，立即拆除对应回落。** 拆除是**里程碑的一部分**，不是「以后再说」——见 [实施路线](/governance/roadmap.md) M2。
4. **不静态链接任何一家。** 仅通过进程边界与各自的 API 交互（★ 也是**许可证考虑**）。

# ★ 代价已知并接受（G25）

回落**两家**而非一家，回落层工程量**约翻倍**，而这些代码 1.0 时**全部删除**。

AI 当时建议只回落 Caddy 一家（评 8.5 vs 7.0），owner 推翻了它。换来的是：**过渡期不必向自己和早期用户解释难看的性能数字**——静态与缓存这两块 nginx 最强。

# 判断一个改动该不该做

[设计原则](/product/design-principles.md) 第七条给了一条可操作的判据：

> **如果一个改动让回落层更难删，它就违反了第七条**——哪怕那个改动本身让回落工作得更好。

能力翻译、配置语义映射、统一两家行为差异，全部因此出局。

# ✅ 进程管理方式（G34，结案）

**复用既有 systemd 单元 + 在枢衡的 unit 里声明依赖。** 枢衡**不拉起、不监管、不重启、不读它们的配置**。

```ini
Wants=caddy.service nginx.service
After=caddy.service nginx.service
```

★ **`Wants=` 而不是 `Requires=`**：回落后端挂掉不该把枢衡一起拖死——**入口还活着并对未实现能力返回 502，好过整个入口消失**。

## 为什么不是「枢衡自己拉起并监管」

1. ★ 本页「四条约束」之上，[设计原则](/product/design-principles.md)第七条给的判据是「**让回落层更难删的改动就违反第七条**」。自建监管会让枢衡长出**进程管理器**这个第二身份，而这部分代码 1.0 时要一起删。
2. ★ G31 之后枢衡在 systemd 下**前台运行、跑在自己的 cgroup 里**，它拉起的子进程会被拖进同一生命周期——**优雅升级时会被一起杀掉**。

★ 两个方案本来都满足第 4 条约束（不静态链接、仅通过进程边界交互），所以决定它的是上面这两条，不是第 4 条。

**1.0 时拆除回落层** = 删掉转发代码 + 从 unit 里删掉这两行。
