# 五个里程碑

| 里程碑 | 名称 | 退出条件（可判定的事实） |
|---|---|---|
| **M0** | 接缝验证 | 一次 `SIGQUIT` + `-u` 优雅升级中，HTTP / TCP 长连接 / UDP 回声**三类零中断**，且能在 Docker 里一条命令重跑 |
| **M1** | 接管一台机 | 一台真实服务器由枢衡承载、跑通冒烟 + 压力（G73） |
| **M2** | 接管两台 | **两台**服务器全部由枢衡承载；回落层已无常态使用（G81） |
| **M3** | 对拍达标 | 每类用例不劣于**该类最强者** 10%；基准脚本与原始数据**可被第三方复现** |
| **M4** | 发布 | 已在生产**连续承载 ≥ 90 天**，且 M3 达标 |

# 每个里程碑要做什么

## M0 · 接缝验证

范围按 G27 收窄：**裸 TCP + 裸 UDP 验 fd 移交，QUIC 推后**。

> 风险本体是「非 Pingora 托管的监听器能否参与 fd 移交」，这与监听器上跑什么协议无关——能移交裸 UDP 的 fd，就能移交 QUIC 的。把 QUIC 排除在外，失败时才能立刻分清是**接缝**的问题还是 **QUIC 库**的问题。

该接缝的带上下文历史实测记录见 [M0 接缝验证](/verification/m0-seam.md)；它记录那次运行的证据，不维护当前里程碑状态。

## M1 · 接管一台机

DSL → 结构化配置 → 运行时全链路；全量原子 load API（Unix socket）；自动 HTTPS（含 `.cn` / `.cc` 双域）；反向代理 + 基础负载均衡 + 主动健康检查 + DNS 定期重解析；未实现能力回落。

线程模型、DSL 指令集、ACME、路径约定与回落层进程管理必须服从 `PLAN.md` 中 D2–D6 的后续拍板记录，见 [待定清单](/governance/open-questions.md)。

## M2 · 接管两台

L4 面、静态文件、磁盘缓存、HTTP/3 **依次自研上线并逐块拆除回落**；Runtime 增量通道 + 临时覆盖层；观测三件套。

★ **拆除回落是里程碑的一部分，不是「以后再说」**——见 [回落层](/architecture/fallback.md) 的第 3 条约束。

★ **顺序由 owner 的负载画像定**HTTP 反代 + 静态站、**有非 HTTP 端口要透传**、有重负载需要磁盘缓存 ⇒ **第一块取 L4 面**，它是三样里唯一「今天就有真实需求、且不依赖任何待定项」的。

D7 / D8 / D11 与 L4 的依赖关系不同；三条的最终结论分别记录为 D8→G82–G84、D11→G103–G105、D7→G113/G114。引用这些决策时以 `PLAN.md` 为准。

## M3 · 对拍达标

与 Caddy、HAProxy、Nginx **三家同机同用例对拍**，不挑软柿子。详见 [性能验收标准](/verification/performance-bar.md)。

## M4 · 发布

文档、`deb`/`rpm` 包、DSL 参考、`nginx.conf` 与 `Caddyfile` 迁移指南、安全披露流程。

★ **发布前需正式审查三家的许可证义务与打包方式**（`PLAN.md` §9 风险表末条）。

「源码看得见」与「可以拿去用」是两件事；M4 是否退出只由 `PLAN.md` 的发布判据决定。

# ★ 退出条件的共同形状

五个退出条件没有一个是「功能做完了」。它们全是**外部可核验的事实**：

- M0 是**测试的退出码**（`tests/m0/run.sh` 非零即失败）
- M1/M2 是**真实域名在真实流量下跑了多久**
- M3 是**第三方能不能复现那组数字**
- M4 是**生产连续承载的天数**

★ 这不是巧合，是 G24 的直接后果。**「能不能真用」不能由实现者自己宣布。**
