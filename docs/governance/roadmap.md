# 五個里程碑

| 里程碑 | 名稱 | 退出條件（可判定的事實） |
|---|---|---|
| **M0** | 接縫驗證 | 一次 `SIGQUIT` + `-u` 優雅升級中，HTTP / TCP 長連接 / UDP 回聲**三類零中斷**，且能在 Docker 裡一條命令重跑 |
| **M1** | 接管一臺機 | 一臺真實伺服器由樞衡承載、跑通冒煙 + 壓力（G73） |
| **M2** | 接管兩臺 | **兩臺**伺服器全部由樞衡承載；回落層已無常態使用（G81） |
| **M3** | 對拍達標 | 每類用例不劣於**該類最強者** 10%；基準指令碼與原始資料**可被第三方重現** |
| **M4** | 發佈 | 已在生產**連續承載 ≥ 90 天**，且 M3 達標 |

# 每個里程碑要做什麼

## M0 · 接縫驗證

範圍按 G27 收窄：**裸 TCP + 裸 UDP 驗 fd 移交，QUIC 推後**。

> 風險本體是「非 Pingora 託管的監聽器能否參與 fd 移交」，這與監聽器上跑什麼協定無關——能移交裸 UDP 的 fd，就能移交 QUIC 的。把 QUIC 排除在外，失敗時才能立刻分清是**接縫**的問題還是 **QUIC 庫**的問題。

該接縫的帶上下文歷史實測記錄見 [M0 接縫驗證](/verification/m0-seam.md)；它記錄那次執行的證據，不維護當前里程碑狀態。

## M1 · 接管一臺機

DSL → 結構化設定 → 執行環境全連線路徑；全量原子 load API（Unix socket）；自動 HTTPS（含 `.cn` / `.cc` 雙域）；反向代理 + 基礎負載均衡 + 主動健康檢查 + DNS 定期重解析；未實作能力回落。

執行緒模型、DSL 指令集、ACME、路徑約定與回落層處理程序管理當初登記為 **D2–D6**，⚠ 這幾條**都已經拍過板** —— 結論在 `PLAN.md` §10（見 [決策紀錄](/governance/decision-log.md)），**它們不在** [待定清單](/governance/open-questions.md) **裡了**。

## M2 · 接管兩臺

L4 面、靜態檔案、磁碟快取、HTTP/3 **依次自研上線並逐塊拆除回落**；Runtime 增量通道 + 臨時覆蓋層；觀測三件套。

★ **拆除回落是里程碑的一部分，不是「以後再說」**——見 [回落層](/architecture/fallback.md) 的第 3 條約束。

★ **順序由 owner 的負載畫像定**HTTP 反代 + 靜態站、**有非 HTTP 連接埠要透傳**、有重負載需要磁碟快取 ⇒ **第一塊取 L4 面**，它是三樣裡唯一「今天就有真實需求、且不依賴任何待定項」的。

D7 / D8 / D11 與 L4 的依賴關係不同；三條的最終結論分別記錄為 D8→G82–G84、D11→G103–G105、D7→G113/G114。引用這些決策時以 `PLAN.md` 為準。

## M3 · 對拍達標

與 Caddy、HAProxy、Nginx **三家同機同用例對拍**，不挑軟柿子。詳見 [效能驗收標準](/verification/performance-bar.md)。

指令碼、環境快照與判定口徑在 [`bench/`](../../bench/README.md)（第一刀，G132 / G139）。
M3 的進度、讀數與結論只看 [`PLAN.md`](../../PLAN.md) §1 與其 M3 一節，本頁不復述。

## M4 · 發佈

文件、`deb`/`rpm` 包、DSL 參考、`nginx.conf` 與 `Caddyfile` 遷移指南、安全披露流程。

★ **發佈前需正式審查三家的授權條款義務與打包方式**（`PLAN.md` §9 風險表末條）。

「原始碼看得見」與「可以拿去用」是兩件事；M4 是否退出只由 `PLAN.md` 的發佈判據決定。

# ★ 退出條件的共同形狀

五個退出條件沒有一個是「功能做完了」。它們全是**外部可核驗的事實**：

- M0 是**測試的結束代碼**（`tests/m0/run.sh` 非零即失敗）
- M1/M2 是**真實網域在真實流量下跑了多久**
- M3 是**第三方能不能重現那組數字**
- M4 是**生產連續承載的天數**

★ 這不是巧合，是 G24 的直接後果。**「能不能真用」不能由實作者自己宣佈。**
